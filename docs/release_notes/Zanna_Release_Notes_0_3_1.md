# Zanna Compiler Platform — Release Notes

> **Development Status:** Pre-Alpha. Zanna is under active development and not ready for production use.

## Version 0.3.1 — Pre-Alpha (DRAFT — unreleased)

<!-- DRAFT: release date TBD. Changes are measured from the v0.3.0-prealpha tag, cut 2026-08-28. -->

### What this release is about

v0.3.1 makes a Zanna game more dependable when it grows beyond a prototype. Ordinary MP3 music plays through instead of stopping after its opening seconds, keeps playing when a loading screen or a slow frame holds up the game loop, and can stream straight from the game's packaged assets. Large scenes bake their lighting with the CPU available to them without changing the result, and they no longer leave later lights or soft light shapes out of the finished image.

The release also gives 3D projects more useful ways to make and show content. Secondary cameras can reuse compatible main-view shadows, models can supply masks from any chosen model axis, and a mesh can be lofted from an authored height profile. Asset preparation can retain sensible levels of detail for a finished scene instead of requiring every piece to be drawn at its highest cost. A decal stays on the animated, curved, or two-sided surface it was projected onto, a mirrored character carries its skinning and morph detail to the other side, and a game can set its own application icon. An off-screen render can be read back the way it would present, tone curve and all, so a portrait or a thumbnail rendered into a texture matches what the player would have seen instead of arriving two and a half times too dark. Characters gained real control over their motion: clips can be aligned on their contact landmarks, a stride can be lengthened or shortened against the pose just blended, a blend tree keeps all of its samples, and a foot on sloped ground keeps the orientation the animation gave it. A set of read-only properties reports what the renderer actually drew — how much of a pose a blend tree is driving, which level of detail a camera chose, whether a mesh will skin at all — so a game can check the picture rather than its own intentions.

Lighting grew to the size of the scenes people are actually building. A light can be given the distance it reaches and keep the falloff it was authored with, a lightmap can carry only bounced and ambient light so baked surfaces sit under live fixtures without being lit twice, and a venue's worth of fixtures can cast shadows — the shadow budget nearly doubled, secondary shadow maps can be sized separately from the main ones, and repeated structural geometry is submitted to the shadow pass in batches. Lens flares add light to the frame instead of covering what is behind them, and translucent images and text keep clean edges on every backend.

Several things a player hits in the first minute are fixed. A game that switches a shared window between 2D menus and a 3D world keeps its cursor, overlay, and displayed size aligned through fullscreen and resize changes, and a 2D game in fullscreen sits centered between equal black bars instead of against the left edge of the monitor. On macOS, turning fullscreen on and straight back off lands on the mode the game asked for last. Switching away from a game clears held input instead of leaving a character walking or accidentally activating a button. Long sessions that load and unload models keep showing the content that is actually loaded, and post-processing no longer lets one camera borrow another camera's exposure or motion history. A hard cut to a new angle now arrives with its picture finished, instead of showing a white or untextured frame while the new view's images load, and a light flare in the new shot fades in rather than popping. The cut also drops the image history that no longer describes the shot, and temporal anti-aliasing checks depth before reusing history, so a background revealed by a moving object stops wearing the color of what was in front of it. Spot and point lights cast the contact shadows the guides already promised, a crowd of repeated props stops re-deriving every frame what it already knows, and a game running picture-in-picture views no longer leaks GPU memory for the length of a session. A point just in front of a 3D camera is no longer reported as on screen with a projection large enough to overflow a game's own arithmetic. On Windows, a 3D game shows its first frame in a fraction of a second instead of after a seven-to-nine-second black window, a game started from the desktop no longer brings a console window along with it, and the Direct3D frame loop stopped waiting on the GPU it had just fed — on one measured scene, a laptop that ran at 9 frames a second with its GPU a third busy now runs between 26 and 43.

Zanna Studio is smoother on a large project and safer when work is interrupted. Search, build output, and workspace services stay out of the way of editing; split editors stay responsive while you type; Save All and background services report failures clearly; and an interrupted workspace-wide change leaves a recoverable record instead of an ambiguous collection of temporary files.

A finished game has a path to a storefront. The new `Zanna.Services` library gives a game its player's identity, ownership and DLC checks, achievements, stats, leaderboards, rich presence, the platform overlay, an on-screen keyboard, and cloud saves through one provider-neutral API, with Steam as the first provider. It also covers what a game sold on Steam grows into: marking moments on the background recording timeline, listing DLC and the running build and beta branch, achievement icons and global unlock percentages, Steam Input actions with their controller glyphs, and Workshop items players subscribe to or publish. The whole surface has been exercised against a signed-in Steam client. Zanna never builds or links against Valve's SDK: the Steam library the game ships is opened at run time, and the same executable runs normally without it — from another store, in CI, or on a developer's machine. `zanna package` can write a SteamPipe build root for Windows, macOS, and Linux depots, every package format now carries the project's asset packs where the runtime looks for them, and a Windows installer built from a project wears that project's name and icon rather than the toolchain's.

Native builds got more trustworthy, and quite a bit leaner. Both backends now allocate registers across a whole function instead of a block at a time, which took a real program's AArch64 build from 105,089 instructions to 55,537 and its spill slots from 9,977 to 200. Ten ways a correct program could be compiled into a wrong one are fixed, on both supported architectures, and real language programs are now compared against the interpreter at every optimization level, so the next one is caught here rather than in a game. A function of your own named like one in the C library — `floor`, say — no longer quietly replaces the real one in a natively linked program. Linux programs that failed to link natively against a current system toolchain link and run. Building the toolchain itself from source on Windows works again, on macOS and Linux the install step became its own script so a failed install can be finished without rebuilding, the Windows renderer reserves room for the whole of the release's larger shadow budget, and a native Windows program recovers from a runtime trap instead of unwinding past it and exits with the exact code it returned. In the language, an inherited field no longer loses to a module global that happens to share its name, and a constant exposed by one module — a cast, a mirror of another constant, or a list literal — keeps its type when another module reads it. A string lent out by a runtime result, such as `Result.UnwrapStr()`, is no longer freed before the call it was passed straight into. An optimized build can no longer leave behind code its own verifier rejects. Every runtime function that returns an object now declares which class it returns, so the compiler stops guessing — and stops guessing wrong for about two hundred of them, such as `Option.Unwrap` and `Result.Unwrap`. Zia's optional narrowing follows `&&`, `||`, and `!`. In the runtime, an object releases the things it owns when it is dropped, reference cycles between class instances can be collected, running out of memory returns a failure instead of ending the process, the temporary strings the runtime builds for its own calls are no longer leaked, and the collector's object table no longer slows down over a session measured in hours.

BASIC grew up considerably. `ON ERROR GOTO` with `RESUME`, `RESUME NEXT`, and `RESUME <label>` actually resumes, where every form used to trap. Strings and objects are released on every path instead of leaking hundreds of megabytes in a long native loop, a `STRING` is never null, `STATIC` class members are shared rather than malformed, comparisons with `NOTHING` work, and namespaced classes, interface calls, and scoped `USING` compile to what they say. A numeric variable read before it is assigned is zero in a native build rather than stack garbage.

#### Highlights

- **MP3 music plays complete, ordinary files (new).** Zanna's from-scratch decoder now supports the common MPEG Layer III variants used by everyday encoders, including variable bit rate, short blocks, joint stereo, MPEG-1, MPEG-2, and MPEG-2.5.
- **Your soundtrack survives a slow frame (new).** Music streaming refills in the background, so asset loading or an unusually long frame does not drain playback into silence.
- **Music plays from your packaged assets (new).** `Music.LoadAsset(name)` streams a WAV, OGG, or MP3 track through the asset manager, so music inside an embedded image or a mounted, compressed pack plays without being unpacked to disk first.
- **A bake uses your CPU and remains repeatable (new).** Lightmaps and probes can use multiple cores while producing the same output regardless of worker count. Large scenes also keep all of their local lights, including rectangular, spherical, and volume lights with their authored shape.
- **Secondary camera views are more practical (new).** A picture-in-picture, security monitor, or in-world screen can reuse compatible shadows from the main view and choose a lower shadow cascade budget without lowering the main view's quality.
- **More of your authored model can drive the material (new).** `Mesh3D.RasterizeUvAxis` can turn X, Y, or Z position into a UV-space mask, useful for applying a material treatment to a model region such as a side panel, sleeve, or depth band. `Mesh3D.HeightLoft` creates shaped geometry from a defined height profile.
- **Detailed scenes stay manageable (new).** Offline asset preparation can retain constrained levels of detail for compatible static content, while the renderer keeps complete lighting results when a scene's light list is crowded. The result is a more graceful quality/performance trade-off for large environments.
- **A light reaches as far as you said it does (new).** `Light3D.Range` is honored for point and spot lights in live shading, clustering, and local shadows, so a fixture stops where you placed its boundary instead of leaking across the scene. An authored falloff coefficient below the old floor survives instead of being clamped, and the previous attenuation curve is preserved when no range is set.
- **A baked scene can sit under live lights (new).** `LightBaker3D.IncludeDirect` lets a lightmap carry sky, emissive, and bounced light only, so baked surfaces can be combined with live analytic fixtures without being lit twice. Probe baking is unchanged.
- **A venue's worth of fixtures can cast shadows (new).** The shadow budget rises from 12 slots to 20, `Canvas3D.SetShadowAtlasResolution` sizes the secondary maps independently of the main ones, and repeated static geometry is submitted to the shadow pass in instanced batches instead of one draw per copy. If the backend cannot prepare the slots you asked for, the frame reports the dropped requests rather than rendering something wrong.
- **Spot and point lights cast the contact shadows they were documented to (new).** The slope-scaled and normal-offset shadow bias was derived for directional maps only, so on a perspective or cube shadow map it collapsed to the constant bias alone. All four backends derive it for every projection type now, which restores contact shadows under objects lit by spot lights and stops striping on surfaces close to the light. Directional shadows are unchanged.
- **Lens flares add light instead of hiding the scene (new).** Flare sprites compose additively from their texture's radial alpha and smoothed visibility, and additive draws preserve destination alpha on Metal, OpenGL, Direct3D 11, and the software renderer — which also cleans up the edges of translucent images and text on Metal.
- **Projected decals and mirrored characters hold together.** Decals follow curved, animated, and two-sided surfaces more reliably, and `Mesh3D.Mirror` reflects skinning and morph detail as well as the visible shape.
- **Animation can be aligned, stretched, and inspected (new).** `AnimBlend3D.SetPhase` and `GetPhase` align clips of different lengths on their contact landmarks rather than by playback rate, `IKSolver3D.SetStrideWarp` lengthens or shortens a stride against the pose that was just blended, a blend tree can hold all sixteen of its samples instead of eight, and a foot placed on a ground normal keeps the orientation the animation gave it instead of pitching upward.
- **A game can check what the renderer actually drew (new).** `AnimController3D.BlendTreeWeight` reports how much of the pose a locomotion tree is driving, `SceneNode.SelectedLod` says which level of detail a given camera chose, `Mesh3D.BoneCount` and `Mesh3D.Skeleton` say whether a mesh will skin at all, and `AnimController3D.AnimationLodSkips` counts the updates an animation rate limit rejected. A character can animate wrongly while every controller-side check reads healthy; these readbacks let a game assert on what a viewer sees.
- **An off-screen render reads back the way it presents (new).** `RenderTarget3D.AsDisplayPixels()` returns the target through the tone curve, exposure, color grade, LUT, and sharpen the same scene would present with, so a portrait, a thumbnail, or a composited inset saved from an off-screen pass matches what a player sees instead of coming back about two and a half times too dark through the mid-tones. `AsPixels` and `CopyTo` are unchanged and keep their scene-referred contract.
- **Your game can look like itself outside the frame (new).** A 2D or 3D canvas can set its application icon from `Pixels`, so supported desktop shells show the game's identity instead of a generic image.
- **Fullscreen single-window games agree with the mouse.** When 2D menus hand a window to a 3D world, the pointer, canvas size, and overlay stay in one coordinate space through fullscreen, resize, and return to the menu. Fullscreen also works on monitor-sized and high-density framebuffers.
- **A 2D game fills the screen the way you expect (new).** A 2D `Canvas` in fullscreen is scaled and centered, with equal black bars on the axis that does not fit, instead of anchored top-left. A 1344×872 game on a 1920×1080 monitor used to leave a 256-pixel band on the right. Drawing stays inside the picture, the pointer reads outside the design when it is over a bar, `Screenshot()` and the canvas size report the designed extent, and the new `Canvas.IsFullscreen()` reports the mode the window is actually in. On macOS, the last of several quick fullscreen and windowed requests is the one that takes effect, where a request made during the transition animation used to be dropped.
- **A point behind the near plane is not on screen.** `Camera3D.WorldToScreen` used to flag a point between the eye and a perspective camera's near plane as visible, with a projection around ten billion pixels from the center — enough to overflow a game's integer distance check and trap mid-game. Every renderer clips such a point, and the query now reports it as not visible while still returning finite coordinates.
- **A Windows 3D game shows its first frame almost immediately (new).** Direct3D 11 shaders are compiled when the runtime is built instead of every time a program starts, removing the seven-to-nine-second black window before the first frame: creating a `World3D` drops from about 8 seconds to about 0.2. The shaders also keep their not-a-number guards now, so skinning, morphs, lighting, motion vectors, and temporal history are protected on Direct3D as they already were on Metal and OpenGL.
- **A Windows 3D game stops waiting on its own frames (new).** The Direct3D 11 swap chain asked for a single back buffer and never bounded frame latency, so the thread that submitted a frame blocked until the GPU had finished it and the two costs added instead of overlapping. Pipelined presentation, a presented-frame snapshot taken only when a game has asked for one, and an instancing check that no longer copies every pair of draws took one authored scene on an RTX 4070 laptop from 9 frames a second to between 26 and 43.
- **A game launched from the Windows desktop opens only its own window (new).** A program started from Explorer, a shortcut, or an installer used to get a console window beside its game window for the whole session, and closing that console ended the game. The console is released when the first window opens, while terminal launches and redirected output behave as before. A lone Alt or F10 press no longer freezes the game in the window-menu loop.
- **Switching away from a game does not leave input stuck.** Losing focus clears held keys, mouse buttons, text, wheel movement, and click history without inventing a release or click. Alt-tab can no longer confirm a control on the way out.
- **A model you released cannot come back as stale geometry.** Long sessions that load and unload content keep drawing the model, material, and morph state currently in use rather than a retired resource that happened to occupy the same memory.
- **Post-processing belongs to one camera at a time.** A second concurrent use of the same temporal post-processing chain is refused with a clear recoverable error, preventing cross-camera ghosting and exposure jumps. Give each active `Canvas3D` its own chain.
- **A camera cut arrives fully textured (new).** `Canvas3D.NoteCameraCut()` tells the renderer that the next frame changes the whole view, so that frame finishes the images it draws instead of paying them out over the following frames — no white or untextured flash on a hard cut — and a flare seen for the first time in the new shot fades in instead of appearing at full brightness. The number of textures a scene keeps ready on the GPU also grew fourfold, so a large environment stops reloading the surfaces behind the camera every time the shot changes.
- **Temporal anti-aliasing survives a cut and a fast subject (new).** A camera cut now drops the image history it cannot reuse. Retained history is rejected where the stored depth no longer matches, so a revealed background stops inheriting the color of whatever used to be in front of it, and `Material3D.TemporalWeight` tunes how much history one material keeps. Motion vectors on Metal and Direct3D 11 are stored as signed floating point, so a subpixel movement is represented instead of being quantized into several pixels of error.
- **A big scene stops paying for its own size (new).** Adding or removing a top-level object no longer recounts the whole scene graph, so building a large world does not get slower the larger it gets; a second camera's view skips the occlusion work only the main view needs; common character and camera updates stop allocating temporaries on every frame; and `Canvas3D.FrameGpuTimeUs` reports real GPU frame time on Metal as well as OpenGL. Gamepad look motion is integrated by frame duration, so a fast machine no longer turns the camera faster than a slow one.
- **Crowds and repeated props stop re-deriving what they already know (new).** `InstanceBatch3D` tracks which instances actually changed, so a parked layer of thousands of copies costs a fraction of its previous per-frame CPU, groups its instances into cells for culling, and reports its retained memory through `InstanceBatch3D.RetainedBytes`. Metal also stopped leaking a GPU allocation on every synchronous texture readback, which a game running picture-in-picture views or render-target mirrors paid for continuously.
- **Studio stays responsive and recoverable on a big project.** Search and output arrive in bounded batches, split views avoid full-document work on every keystroke, and an interrupted workspace-wide rename or replace leaves a durable recovery record.
- **Your game can talk to Steam without Zanna depending on it (new).** `Zanna.Services.Platform` starts a provider and reports the player's identity, language, license, online state, and installed DLC; `Achievements`, `Stats`, `Leaderboards`, `Presence`, `Overlay`, `OnScreenKeyboard`, and `Cloud` cover the features a released game is expected to have. Slow operations return a `Zanna.Services.Request` you poll across frames, platform callbacks arrive as polled events, and a game with a canvas has the provider pumped for it. Steam is loaded from the redistributable you ship beside the executable; without it every member returns a neutral value, so one binary runs everywhere.
- **The rest of what a Steam game uses (new).** `Zanna.Services.Timeline` marks events, game modes, and phases on Steam's background recording and reads back what was recorded. `Platform` lists DLC, reports the build and beta branch, and reads the launch parameters of a `steam://run` link. `Achievements` reads each achievement's icon and its global unlock percentage. `ActionInput` binds Steam Input action sets and layers, reads digital and analog actions, shows controller glyphs, and drives rumble and LEDs. `Workshop` subscribes to, downloads, queries, creates, updates, and deletes Workshop items. Each group degrades on its own when an older Steam library lacks it, and the new `steam-check` example exercises every services class against a signed-in client.
- **Package straight into Steam depots (new).** `zanna package --target steam-windows`, `steam-macos`, or `steam-linux` writes a SteamPipe build root with per-platform content, an app build script, and a manifest of sizes and SHA-256 hashes. Packaging each platform into the same root builds a multi-depot release, the executable and the Steam redistributable are checked for a matching OS and architecture, and a macOS build gets the entitlements Steam needs before it is signed.
- **Every package format ships your asset packs.** `zanna package` generates the project's pack groups once and places them where the runtime mounts them — the app bundle's resources on macOS, beside the executable on Windows, in tarballs and Steam depots, and in the installed library directory for deb, rpm, and Linux bundles. Packs beside a POSIX executable are also found now; a name comparison off by one character meant they never were.
- **A Windows installer wears the product it installs (new).** Setup's window captions, brand panel, and dialog icons were hardcoded to the Zanna toolchain, so an application package installed itself under the compiler's wordmark and icon. Setup now brands itself from the project's `package-name` and `package-icon`, which travel in the package as a resource it reads and never installs, so the installed file set and the reported install size are unchanged.
- **Native code is allocated across the whole function (new).** Both backends replaced their block-local register allocator with one that sees a function's entire control flow, so a value stays in a register across block boundaries instead of round-tripping through the stack frame at each one. Across twenty programs at `-O2`, AArch64 falls from 224,277 to 137,951 instructions and from 18,783 spill slots to 292, and x86-64 from 224,706 to 190,872 instructions and from 4,705 spill slots to 1,784, with no program's instruction count rising.
- **Native builds compile your program, not a variation on it.** Ten miscompiles are fixed. A value copy could be discarded while a conditional branch still read it, an x86-64 division could have its result overwritten by a forwarded store, and an AArch64 large constant could be expanded through a scratch register that already held one of the instruction's own operands. On x86-64, a 32-, 16-, or 1-bit value was stored and loaded as eight bytes, so writing a `Boolean` field at the end of an object wrote past the object. A loop variable that a trip left unchanged could lose its register, a loop that only ever ends by trapping could be folded away, and a flag set inside a loop could be given its answer before the loop ran — which is how a native build of a game handed out a base on every pitch and looked its left-handed pitcher up on the wrong roster.
- **A function of yours named like a C library function stays yours (new).** A natively linked program shares one flat symbol namespace with the C runtime, so a `func floor` was emitted as the plain symbol `floor` and satisfied libm's own internal reference to it — the runtime's ellipse rasterizer then called the game's function instead of the real one. The link succeeded and nothing diagnosed it; only native builds computed the wrong answer. Names that can collide with the C and POSIX libraries are emitted with a `zn_` prefix on both backends now, while `main` keeps its spelling.
- **A native build is now checked against the interpreter on real programs (new).** Six language fixtures covering classes, lists, and nested control flow run natively at each optimization level and are compared with their interpreted result, and the register-allocation oracle now checks the machine-code cleanup passes as well as the allocator. Both found defects on their first run. The previous synthetic checks never reached these shapes.
- **An optimized build cannot leave code the verifier rejects.** Strength reduction no longer removes the arithmetic an earlier pass relied on to prove an operation could not overflow, which could make an otherwise correct program fail verification at `-O2`. A standing gate runs the whole optimization pipeline over that shape and requires the result to verify.
- **An exported constant keeps its type across modules.** A top-level `final` whose value is a cast, a list literal, or a mirror of a constant from another module now carries its real type into the importing module instead of arriving as an untyped object. Ordinary arithmetic on such a constant used to fail verification, and reading an imported list with `length()` or `get()` stopped the compiler on an internal error, in code that was never wrong.
- **A runtime call returns the class it says it does.** About 1,050 runtime functions used to return a bare object whose class each frontend guessed from the method's owner or name, and about 200 of those guesses were wrong — `Option.Unwrap` and `Result.Unwrap` were typed as their own class, `Menu.AddItem` as a `Menu`, and decryption, `Tls.Recv`, and `Http.PostBytes` as their static class instead of `Bytes`. Every result now declares its class, and a standing audit keeps it that way. A value typed `Zanna.Core.Object` still accepts any runtime object but needs an explicit `as` to become a specific class.
- **Zia narrows optionals through boolean logic.** `if (a != null && b != null)` narrows both values inside the branch, and `if (a == null || b == null) return;` narrows both after the guard. `List`, `Map`, and `Set` gain `IsEmpty`, a name exported by two bound modules is reported as ambiguous rather than undefined, and warning W015 no longer fires on the target of a plain assignment.
- **BASIC error handling resumes, and BASIC programs stop leaking (new).** `RESUME`, `RESUME NEXT`, and `RESUME <label>` continue the program as the language describes, through one error dispatcher per procedure. Every `STRING` and object variable, parameter, field, and result owns its reference and releases it, so a native loop of a million string or object operations no longer grows by hundreds of megabytes, and a borrowed runtime result is no longer released twice. A `STRING` is never null, so `IF name$ = "" THEN` is true for one never assigned. `STATIC` fields, methods, constructors, and destructors work; `obj = NOTHING` and `obj IS NOTHING` compile; `HEX$`, `OCT$`, `SPACE$`, and `STRING$` are real built-ins; and namespaced classes, interface method calls, and `USING` inside a namespace resolve correctly.
- **Natively linked Linux binaries build against current toolchains.** The bundled linker handles the full set of global-offset-table relocation forms modern compilers emit, so programs that previously failed to link on an up-to-date Linux distribution now link and run.
- **Building from source on Windows works again.** Four breakages had collected in code only Windows compiles, so the toolchain, Zanna Studio's native helper, and the test suite build, link, and pass their checks with MSVC, the PowerShell build scripts no longer stop on a tool's warning when their output is captured — and Direct3D 11 has storage for every slot of the release's larger shadow budget rather than half of them. A native Windows program recovers from a runtime trap instead of unwinding past it, and exits with the exact code it returned, so a negative exit code matches the interpreter.
- **An install that fails can be finished without rebuilding (new).** On macOS and Linux the install step is its own script, so a `sudo` prompt that times out at the end of a long build no longer means running the whole build again.
- **A long session stops leaking and stops guessing.** `Zanna.Runtime.GC.Collect()` reclaims strong reference cycles between class instances, an object releases its fields when it is dropped, and running out of memory raises a failure you can handle rather than ending the process. `File.ReadAllText` reports a file that grew while it was being read instead of handing back the prefix it managed to get. The temporary strings the runtime creates for map keys, error results, and widget labels are released — 300,000 error results used to cost 127 MB — and the collector's table of tracked objects no longer fills with deleted-entry markers that made every lookup scan the whole table after hours of play.
- **Dialogue and particle trails look right.** Typewriter dialogue reveals accented and non-Latin text one character at a time instead of one byte at a time, and a dialogue bubble stays inside a small canvas. Particle trails sort correctly against each other, and a short trail fades over its real length instead of vanishing early.

### Audio

- Imported MP3 music now supports the normal Layer III files made by common tools: mono, stereo, joint stereo, constant and variable bit rates, and the MPEG-1, MPEG-2, and MPEG-2.5 families.
- Music refills on a background worker. A loading screen, asset batch, or long frame no longer makes a playing track fall silent; `Audio.Update()` still handles crossfades and playlist progression.
- `Zanna.Audio.Music.LoadAsset(name)` loads a track through the asset manager — embedded images, mounted and compressed packs, and loose files alike — detects WAV, OGG, or MP3 from its leading bytes, and streams it from memory. A missing or undecodable asset returns null. Streaming a WAV from memory decodes at the stream's own cursor, so seeking and rewinding behave exactly as they do for a file.

### 3D rendering and baked lighting

- Lightmap and probe baking can use available CPU cores while retaining deterministic output. It remains suitable for incremental editor work, and scenes with many local lights no longer stop contributing after the first sixteen.
- Render-target views can inherit compatible main-camera shadows with `Canvas3D.SetRenderTargetShadowInherit(true)` and can independently limit their cascades when a cheaper secondary view is the better choice.
- An off-screen render can be read back the way it presents. `RenderTarget3D.AsDisplayPixels()` returns an owned copy of the target's display-encoded mirror — the tone curve and exposure, color grade, LUT, anti-aliasing, and sharpen that the same scene goes through on its way to a window — so a portrait, a thumbnail, or a composited inset saved from an off-screen pass matches what a player sees. `AsPixels` is scene-referred by contract: a face texel at linear 0.25 is written as 64/255, where presenting it through an ACES chain at exposure 1.10 reads about 170/255, so every such image came back roughly two and a half times too dark through the mid-tones with banding in the shadows. `AsPixels` and `CopyTo` are unchanged and stay scene-referred for scopes and linear compositing, and a target whose last frame did not end on a canvas with a usable post-processing chain returns the same bytes from both. Governed by ADR 0368.
- The software renderer computes depth the same way the GPU backends do, so thin geometry and terrain stop flickering or dropping out at grazing angles, and it now applies the same clustered-light selection, so a software frame is lit like a GPU frame. When a scene's light index pool fills, the lights that overflowed still light the scene instead of being dropped. A material that is both unlit and PBR-workflow keeps its emissive term, as it always had on OpenGL, Metal, and Direct3D 11 — the case that matters is a small bright object kept deliberately out of the lighting so it cannot go black against a clipped light pool, which used to render dark in a software frame. Legacy unlit materials take their emissive map in the albedo pass, unchanged.
- A mesh, material, scene node, or morph target that you released cannot be drawn again when a newly loaded resource lands at the same address — a level change no longer paints the previous level's geometry into the new one. And a temporal post-processing chain belongs to one canvas, so a picture-in-picture view cannot inherit the main camera's exposure and motion history.
- A hard camera cut can tell the renderer what is about to happen. `Canvas3D.NoteCameraCut()` marks the next frame as a change of view: that frame completes every image it draws instead of spreading the work across the per-frame upload budget, the motion blur carried over from the old angle is discarded, and a lens flare in the new shot fades in from nothing rather than showing at full brightness for a frame. A texture being drawn for the very first time has nothing to stand in for it, which is what produced the white or untextured frame on a cut. The number of textures kept ready on Metal, OpenGL, and Direct3D 11 rose from 512 to 2,048, so a large environment keeps the surfaces behind the camera rather than reloading them for every shot change. The software renderer applies the motion and flare part of the hint without needing anything from the backend.
- A cut also discards the temporal anti-aliasing history it cannot reuse. Two unrelated shots can hold surfaces at similar depths, so depth validation alone cannot reject the old image; the cut now invalidates retained color and depth and the stored previous camera on the software, Metal, Direct3D 11, and OpenGL backends, and restarts the jitter sequence. Allocated storage, exposure adaptation, and the selected chain are kept.
- Temporal history is validated against depth. The retained image carries a matching depth plane, and a reprojected sample is rejected unless its stored depth agrees with the reprojected depth within a distance-scaled tolerance, so a background revealed by a moving object stops inheriting the color that used to cover it. The depth sample is nearest rather than interpolated, so an occlusion boundary cannot invent a surface between two real ones, and a reprojection that lands off-frame is dropped instead of being pulled to the border.
- `Material3D.TemporalWeight` scales how much validated history one material keeps. It defaults to 1, clamps to 0 through 1, is preserved by `Clone` and `MakeInstance`, and is captured when a draw is queued, so editing a material later cannot change a frame already submitted. Anti-aliasing by edge detection and motion blur are unaffected.
- Motion vectors are stored as signed floating point on Metal and Direct3D 11, and on OpenGL wherever a floating-point scene target is available. The previous 8-bit encoding could not represent standing still — its smallest step was several pixels at ordinary resolutions — which is what made temporal history land in the wrong place on a slow camera pan. All three GPU backends also carry a history depth attachment now, so GPU history is rejected on the same evidence the software path uses.
- Unchanged geometry stays on the GPU across frames in a stadium-sized scene. Each backend keeps 512 static mesh identities resident rather than 256; an authored venue passes 256 once its shadow and main-view detail bands are counted, so the old bound re-uploaded geometry that had not changed on every frame. The limit counts entries rather than bytes, and eviction, refresh on edit, and reused-handle rejection are unchanged.
- Building a large scene no longer gets slower as it grows. Adding or removing a top-level object used to recount the entire scene graph, which made repeated insertion cost rise with the square of the scene size — a stadium-sized startup spent about a quarter of its main-thread time attaching objects, most of it in that recount. The count is observed when something asks for it instead.
- A second camera's view costs less than a second full frame. An off-screen or view-model pass skips the occlusion work that only the main view needs, keeps its own depth snapshot so alternating transparent passes stop churning, and can cap its own shadow cascades; on Metal, a run of shadow slots no longer emits an empty full-resolution pass between each one. `Canvas3D.FrameGpuTimeUs` reports real GPU frame time on Metal now, alongside OpenGL.
- An instanced batch remembers what changed. `InstanceBatch3D` used to re-check, re-copy, re-derive, and re-cull all of its instances on every `DrawInstanced`, so a stationary crowd of several thousand copies cost milliseconds of CPU per frame for doing nothing. Writes now widen a dirty range that the per-frame work follows, a batch that supplies its own previous matrices skips the canvas motion-history lookup, and a batch above 64 instances keeps a cell grid whose per-cell bounds let culling accept or skip whole clusters. Motion history stays exact: structural changes and uninitialized state still copy everything. `InstanceBatch3D.RetainedBytes` reports the batch's retained CPU storage so resource accounting can measure it rather than estimate it.
- Several per-frame costs that grew with scene size are gone. The scene spatial index validates an entry through the node itself instead of a registry lookup per node per query, a single dynamic mesh no longer forces a full parent-chain rescan of every other node, per-instance normal matrices take a fast path for uniformly scaled rotations, the active light limit is computed once per frame instead of once per queued draw, and instanced draws pack directly into their transient buffer slice rather than being staged and copied twice.
- Metal stopped leaking GPU memory on synchronous texture readbacks. Render-target mirrors, composited insets, and probe captures call that path outside any frame, so its command buffer and blit encoder were never released and each call retained one readback-sized allocation for the life of the thread — roughly 35 MB per second with live picture-in-picture views. That path and mipmap generation now run inside their own pool, and the sampler table is released with the context.
- `Canvas3D.SetDepthOnlyShading(true)` tells the software renderer that nothing will read the frame's color, so it runs vertices, clipping, and the depth test but skips per-pixel shading. Draw counts, occlusion, and hitch counts are unchanged, which makes it useful for automated runs that drive the real 3D pipeline and assert on state rather than pixels. GPU backends ignore the flag.
- Character movement, camera placement, and third-person camera follow stop allocating temporary objects on every frame, so a long play session builds up far less garbage. Mouse look stays immediate; gamepad-stick look is integrated by frame duration, so a fast machine no longer turns the camera faster than a slow one.
- In a large world, objects are converted to camera-relative coordinates before culling rather than after, so distant geometry stops being culled away while it is still on screen, and a frame that overflows its draw budget reclaims those slots instead of losing them for the rest of the session. Continuous-collision candidates keep a deterministic full-scan fallback, a navigation mesh built from overlapping source geometry no longer duplicates triangles, and an FBX file is read from memory instead of a temporary file on disk.
- `Camera3D.WorldToScreen` reports a point as visible only when it lies at or beyond a perspective camera's near plane, or in front of the eye for an orthographic camera. A point between the eye and the near plane is clipped by every renderer, and its perspective divide is unbounded: a torso a hair in front of the eye projected to about 10¹⁰ pixels while flagged visible, and a game's per-frame actor pick squared that as a 64-bit `Integer` and trapped on overflow. Screen coordinates are still written when the result is 0, so a caller that ignores the flag gets finite values, but they are only bounded when it is 1.
- Dialogue reveals by Unicode character rather than by byte, so accented and non-Latin text appears one glyph at a time, and an anchored dialogue bubble stays inside a small canvas. Particle trails are sorted against one another and a short trail fades over its actual length.

#### Lighting at venue scale

- `Light3D.Range` now bounds point and spot lights everywhere they are used — live shading, clustering, and local shadow projection — using the same smooth cutoff the light baker already applied, so a fixture's reach in the final frame matches the one you authored. A range of zero keeps the previous attenuation curve, so existing scenes are unchanged.
- An authored attenuation coefficient is kept as written. The fallback used when no coefficient is given is separate from the numerical minimum now, so a value below the old `0.001` default is honored instead of being silently clamped. GPU area-light decay and the glTF and FBX range conversions use the same normalization.
- `LightBaker3D.IncludeDirect` (default true) can be set false to bake a lightmap that omits direct illumination at the surface it lands on while keeping sky, emissive, and bounced energy. That makes a baked atlas usable underneath live analytic fixtures — a stadium lit by real lights over pre-lit structure — without double-lighting the result. Probe-grid baking is unaffected.
- Lens flares compose additively, from the flare texture's radial alpha and a smoothed visibility term, so a flare brightens the scene behind it instead of masking it. Additive draws preserve destination alpha on Metal, OpenGL, Direct3D 11, and the software renderer, and Metal's premultiplied overlay composites as source-over — which also fixes fringing on translucent images and text.
- General shadow capacity rises from 12 slots to 20. Slots four and above can use their own tile size through `Canvas3D.SetShadowAtlasResolution(pixels)` — 64 to 4096, or zero to inherit the `EnableShadows` resolution — with `ShadowAtlasResolution` reading it back, so a 4096 primary map can sit alongside cheaper 1024 secondaries. The backend is told the required slot extent and both resolutions before any tile renders; if it cannot prepare them, the frame is left unshadowed and the dropped requests are reported rather than producing a half-correct picture. On OpenGL, primary and secondary shadow storage are separate, so the smaller secondary resolution is actually honored.
- Repeated static geometry — the same fixture, railing, or seating module placed many times — is grouped by exact draw state and submitted to the depth pass as instanced draws instead of one call per copy. Software, deformed, and particle casters keep per-mesh submission.
- Spot lights and point-light cube faces receive the shadow bias the guides already described. Every backend offsets a shadow receiver along its normal by about one and a half shadow texels and scales its comparison bias by surface slope, but the texel size and depth scale behind both were derived for orthographic maps only: on the GPU backends they stayed at zero for a perspective map, leaving only the constant `SetShadowBias`, and the software renderer applied an orthographic texel size and folded its slope term into the base bias. One shared derivation now covers every projection type, so a spot-lit scene keeps contact shadows under objects and occlusion under overhanging structure at a normal bias value instead of needing an extreme one. Directional shadows, the bias formula, and the slope clamp are unchanged.

### 3D assets and materials

- `Mesh3D.RasterizeUvAxis` produces a UV-space coordinate map from the model's X, Y, or Z axis. It is useful when a material needs a mask that follows a model region without hand-painting one.
- `Mesh3D.HeightLoft` builds shaped mesh geometry from an explicit height profile. Asset preparation can also retain constrained levels of detail for compatible authored geometry, giving large scenes a controlled quality/performance path.
- `Mesh3D.Mirror(mesh, skeleton)` mirrors the visible mesh, skinning influences, and morph targets, so a paired asymmetric prop can genuinely move to the opposite hand.
- `Material3D` projected decals follow animated geometry and preserve lighting on curved and two-sided surfaces, making markings such as numbers, logos, signage, and wear more dependable.
- `Canvas.SetIcon(pixels)` and `Canvas3D.SetIcon(pixels)` let a game provide its own application icon on supported desktop platforms.

### Animation and character motion

- `AnimBlend3D.SetPhase(state, phase)` and `GetPhase(state)` read and set a state's normalized clip time, so clips of different durations can be aligned on their contact landmarks instead of by playback rate. A looping state wraps, including negative input; a non-looping state clamps; a non-finite value becomes zero. The setter moves only that state's clock: it evaluates no pose, emits no events, and changes no speed or weight.
- A blend tree can use all sixteen of its samples. The blender's inline state capacity rose from eight to sixteen, so a directional walk, jog, and sprint tree stops silently losing half of what it was given.
- `IKSolver3D.SetStrideWarp(direction, scale, maxOffset)` and `ClearStrideWarp()` lengthen or shorten a stride against the pose that was just blended, rather than against a foot position read a frame early. Scale is bounded to 0.5 through 1.5 and the offset is clamped to the limit you give, with animated height and chain lengths preserved. `SetTarget` returns the solver to absolute targets.
- A foot placed on a ground normal keeps the orientation its animation gave it. The hint now applies only the shortest-arc correction from the pose's own up direction to the surface normal, so bending a leg to reach a mark no longer pitches the shoe upward on flat ground. An explicit target rotation keeps its previous behavior and its precedence.
- `AnimController3D.BlendTreeWeight` reports how much of the pose an attached blend tree is driving: 1 when the tree owns the palette, the ramped value while a fade is in flight in either direction, and 0 with no tree attached. A fade that never completes leaves the base layer's clip playing under tree-driven movement, which reads to a player as a character sliding along the ground, and nothing could previously witness it.
- Four read-only properties report what the renderer actually did with a character, rather than what the controller intended. `Mesh3D.BoneCount` and `Mesh3D.Skeleton` say whether a mesh carries skinning data and which skeleton it is bound to — a level-of-detail mesh with no skin, or a mirrored copy bound to a foreign skeleton, draws as static geometry under a perfectly healthy controller. `SceneNode.SelectedLod(canvas, camera)` says which level a given view chose, matching on both the canvas and the camera and never disturbing the selection it observes. `AnimController3D.AnimationLodSkips` counts the `Update` calls the animation rate limit rejected, so a game can prove its own throttle never fired on a moving character. None of the four evaluates a pose or advances a clock.

### Fullscreen, windows, and input

- A game that uses one window for 2D menus and a 3D world keeps its pointer, 3D extent, and 2D overlay in the same public coordinate space. The alignment remains correct across fullscreen, resize, scale changes, and handing the window back to the menu.
- Fullscreen accepts monitor-sized and high-density framebuffers rather than retaining a stretched window-sized frame.
- Focus loss clears held input and transient input state without generating a release or click. Returning to the game begins from a clean physical press.
- A 2D `Canvas` in native fullscreen is scaled uniformly and centered, and the remainder on the other axis becomes equal black bars. Primitives, blits, gradients, flood fills, and clips are transformed by scale and offset, so drawing stays inside the picture, and `Clear` paints the picture with its color and the bars black. The pointer maps through the same transform, so a cursor over a bar reads below zero or past the designed extent. `Screenshot()`, the window size, and resize events report the designed extent, matching `Width` and `Height`, and the scaled picture's size is carried exactly so an odd remainder cannot round it away from the design. The offset belongs to the 2D canvas: it is withheld while a `Canvas3D` borrows the window and restored when the window comes back, so a single-window game that fits its own design inside the 3D view is unaffected.
- On macOS, every fullscreen or windowed request is recorded as the mode to reach. The system's fullscreen switch animates and ignores a second switch while it runs, so `Windowed()` called about 100 ms after `Fullscreen()` used to be dropped, leaving the window and the game disagreeing about the mode. A request made during the animation is now applied once it lands.
- `Zanna.Graphics.Canvas.IsFullscreen()` reports whether the window is actually fullscreen, as `Canvas3D.IsFullscreen` already did. After `Fullscreen()` or `Windowed()`, the value reaches the new mode over the following frames on macOS and X11, so a game that must act on the finished change polls it.

### Native code generation and linking

- Native code is allocated across the whole function. Both backends ran a block-local register allocator, which had to hand every value that crossed a block boundary to the stack frame and take it back on the other side; they now share one allocator built on live intervals over the function's control flow, with the block-local path deleted rather than kept as a fallback. Across the twenty benchmark and demo programs at `-O2`, AArch64 drops from 224,277 to 137,951 instructions, 40,670 to 11,224 frame accesses, and 18,783 to 292 spill slots, and x86-64 from 224,706 to 190,872 instructions, 24,434 to 14,736 frame accesses, and 4,705 to 1,784 spill slots — no program's instruction count rose. On AArch64 the chess example at `-O2` goes from 105,089 instructions with 9,977 spill slots to 55,537 with 200, and from 12,381 frame-offset prefixes to 64. Governed by ADR 0339.
- Ten ways a valid program could be miscompiled are fixed. Three came from register allocation and instruction expansion. A copy could be eliminated while a use of its destination sat behind an in-block conditional branch — the kind emitted by an overflow trap or a zero test — leaving that branch reading an undefined value. On x86-64, a stored value could be forwarded into a later load across a division, silently overwriting the registers the division defines. On AArch64, expanding a wide constant could choose a scratch register that already held one of the instruction's own operands, and the instruction scheduler did not account for those expansions writing scratch at all.
- Three more were found through a native build of a real game whose interpreted run was correct, and each is reproduced without the game. On AArch64, liveness read an instruction's operands in written order and treated a destination as killed before a source naming the same register was seen, so a loop parameter copied to itself on the back edge — the shape an unchanged loop variable takes — dropped out of the loop's live set and had its register handed to something else. Constant propagation left a trap-kind query that takes no operands stuck at the bottom of its lattice, so the comparison it fed never resolved, the loop's back edge was never considered reachable, and the loop counter folded to its initial value. And the post-allocation loop hoister moved a constant assignment out of a loop whenever the register had no other definition inside it, without asking whether the loop was entered with that register already live — which is exactly the shape of `found = false` before a loop that sets it to true on some trips, so the flag held its inside-the-loop answer before the loop ran.
- A fourth was found by the register-allocation oracle rather than by a program failing. Store-to-load forwarding could keep a value in a reserved scratch register across a wide-offset frame access whose expansion overwrites that register. Both the store/load forwarder and copy propagation now end a tracking window at any instruction that clobbers reserved scratch or performs a call.
- Two earlier passes were corrected the same way. On AArch64, the store forwarder counted register moves and stores as clobbers but not immediate moves, so a store whose source register was reloaded with a constant immediately afterwards could still be dropped at a join. In IL reassociation, operand leaves were ranked by temporary number, and once an earlier pass renumbered or inlined them that order no longer matched block order, so a leaf defined late could be handed to a node that runs before it. The pass now validates the whole assignment against each node's definition point first and canonicalizes the root's operands instead when any leaf would be used early.
- A tenth was in x86-64 memory access. `i1`, `i16`, and `i32` loads and stores used 8-byte moves, so a narrow value read or overwrote the neighboring bytes of a packed object field, and a trailing `Boolean` field wrote past the end of its heap object. Each width now transfers exactly its own bytes, as the interpreter does: a byte, word, or doubleword store, and a zero-extended `i1` or sign-extended `i16` and `i32` load.
- A no-return trap call reads only the registers it actually passes. The call instruction carries no arity, so every branch-and-link was treated as reading the full argument register set, and a trap block reached from a hot loop pinned that loop's scratch registers around its back edge. The runtime's no-return helpers have fixed integer-only prototypes, so their argument counts are declared; a callee of unknown arity keeps the conservative set.
- Compiled output is checked against the interpreter on real programs now. Six language fixtures — control flow, loops with break and continue, list and map statistics, class methods, numeric algorithms, and advanced control flow — run natively at each optimization level and are compared against their interpreted result under a new `differential` test label, and the two new loop fixtures run interpreted and natively at every level. The register-allocation oracle re-interprets each generated seed after the machine-code cleanup passes rather than only after allocation. Both lanes found defects on their first run.
- A function you define cannot displace one in the C library. A natively linked program shares a single flat symbol namespace with the C runtime it links against, so a Zia `func floor` emitted as the plain symbol `floor` satisfied libm's own internal reference to it, and the runtime's ellipse rasterizer called the game's function instead of the real one. Nothing diagnosed it: the link succeeded and the program silently computed wrong answers, or trapped, only in native builds. Both lowering paths now rename any symbol the module defines that matches the C and POSIX names a program can collide with, giving it a `zn_` prefix and rewriting every reference to it, so that is also the name a profiler or debugger shows. An undefined reference such as `setjmp` still resolves to the C runtime, `main` is deliberately not renamed because it is the native entry point, and Zanna's own runtime was never exposed because its exports are already `rt_`-prefixed.
- Native executables carry their function and object symbols by default, so a profiler or debugger shows names instead of addresses; `zanna build --strip-symbols` is there when size matters more.
- The optimizer no longer reuses a loaded value across a write that another path can reach, which used to hand a stale value to code that ran after it, and a provisional trap decided on early is withdrawn once the values feeding that operation turn out not to be what the optimizer assumed — so a program stops trapping at runtime on a path that is actually fine.
- An optimized build no longer leaves code the verifier rejects. Checked arithmetic is demoted to the plain form whenever the optimizer can prove the operation cannot overflow, and loop strength reduction could then delete the very arithmetic that proof rested on, leaving a plain add, subtract, or multiply the verifier refuses. Strength reduction now checks, before it changes anything, whether the values it is about to replace feed an instruction whose acceptance depends on that range, and leaves such a loop entirely alone. A new standing gate runs a whole named optimization pipeline over the reduced case and requires the result to verify, so no future pass can reintroduce the shape.
- Native code zeroes stack allocations the way the IL defines, on both AArch64 and x86-64, so a local read before assignment returns zero instead of whatever the stack held; stores the optimizer can prove dead are removed. The same change stops IL passes from reusing a value id that was already in use, which had turned a loop index into a stack address in a native build of the chess example.
- The bundled native linker keeps up with current system compilers on Linux. Every global-offset-table relocation form in the ABI is relaxed rather than only the `mov` form, plain references to symbols defined in the same link get link-time slots synthesized for them, and one more C-library symbol is classified correctly — so programs that failed to link natively on an up-to-date distribution now link and run.
- On macOS, the bundled native linker resolves differences between two symbols, the relocation form optimized C objects carry in their exception tables, and knows one more system math entry point the compiler emits at higher optimization levels. Object files built with optimization link natively instead of being rejected.

### Runtime

- An object releases what it owns when it is destroyed: a class with fields holding strings, sequences, or other objects gets a destructor that frees them, base destructors run in order without double-releasing, and runtime-owned objects release their fields on their final drop. Runtime calls declare whether the value they hand back is yours to keep or borrowed, so a returned string or sequence is neither leaked nor freed twice. A borrowed string result used directly as a call argument — `Result.UnwrapStr`, `Result.UnwrapErrStr`, or `Option.UnwrapStr` — is retained for the call in both Zia and BASIC, where it used to be released after the `Result` or `Option` that owned it had already freed it. `Zanna.Runtime.GC.Collect()` also reclaims strong reference cycles between class instances, which reference counting alone could never free.
- Runtime object results declare their class. 1,047 definition rows were checked against the C code behind them and now name `obj<Class>`, a typed sequence, or `obj<Zanna.Core.Object>` when the class depends on the value; the 84 results that may legitimately be a string or a boxed scalar stay bare and are listed explicitly, and an audit enforces that list and that every declared class exists. Zia's and BASIC's owner-class and method-name heuristics are deleted rather than kept as a fallback. `Zanna.Game.Entity`, `Behavior`, `Config`, `SceneManager`, and `Zanna.Game2D.LevelDocument` become real runtime classes, `AnimStateMachine.StateName` returns a string as it always did in C, and `Zanna.IO.Assets.List` and `LoadBytes` return a string sequence and `Bytes`.
- Running out of memory is reported as a failure you can act on across collections, files, networking, threading, and media, rather than ending the process. `File.ReadAllText` reports a file that grew while it was being read instead of returning the prefix it got.
- Temporary strings the runtime creates for its own calls are no longer leaked. Hundreds of call sites passed a freshly copied string to an API that only borrows it — map keys, JSONPath lookups, error results, promise errors, button labels — and never released the copy; 300,000 error results grew memory by 126.7 MB and 300,000 map writes with a literal key by 26.5 MB. String literals now use the immortal literal cache, and every other temporary is released after the call.
- The collector's tracked-object table no longer degrades over a long session. It deleted entries by leaving markers and rehashed only as the live count grew, so a stable population could eventually fill every slot, and each failed lookup — including the one made whenever an ordinary object is freed — scanned the entire table. Deletion now shifts following entries back into the hole with their collector state intact.
- A string literal used in a loop is created once and reused instead of rebuilt on every pass, and a runtime handle used repeatedly is validated against a recent-use cache, so hot loops spend less time on bookkeeping. On macOS, traps and finalizer recovery no longer pay a signal-mask system call each time.
- `File.ReadAllLines` no longer adds an empty line after a final line terminator, so it round-trips `WriteAllLines`, and boxed-string accessors accept a raw string stored in an object slot, as `Seq.GetStr` already did.
- A re-raised error reports its real message. `Zanna.Runtime.Unsafe.RaiseKind` raises with the retained thrown text or the error kind's default message, where a re-raise — including Zia's typed-catch rethrow — used to report `Unknown trap`.
- A runtime built without graphics compiles and links again. That configuration is selected explicitly and also automatically on a Linux host without X11 development headers, and because nothing built it, the changes made since early August had left it with eight source files that no longer compiled, 336 public entry points and 33 internal hooks with no definition, 65 duplicate definitions, seven stubs whose signatures had drifted, and color and text-width helpers that disagreed with the real ones. Every unavailable member now follows its class's contract — constructors trap, loaders return an error `Result`, queries return documented fallbacks — the color and font helpers share one implementation with the graphics build, and a completeness check over every runtime entry point runs as a test.

### Zia

- Optional narrowing understands `&&`, `||`, and `!`, so a compound null check narrows every value it tests, inside the branch or after an early return. `List`, `Map`, and `Set` have a read-only `IsEmpty`, including through optional chains. A name exported by more than one bound module reports "Ambiguous identifier" and asks for a qualified name instead of "Undefined identifier", and W015 no longer warns about the target of `r = 5`.
- An exposed constant keeps its type when another module reads it. A file module's exports are captured immediately after the file is read, so a top-level `final` that had not been typed by then was exported as an untyped object. Three forms are typed in time now: a constant whose value is a cast keeps the cast's type; a constant whose value is a list literal becomes a list of its elements' common type, so `["a", "b"]` is a `List[String]` and a mix of `Integer` and `Number` elements folds to the common numeric type; and a constant that mirrors another constant — in the same file or through a bound module, including a chain of re-exports — copies the type it mirrors, list finals included. Ordinary arithmetic on such an imported value used to be rejected by the IL verifier, and reading an imported list constant through `length()` or `get()`, directly or through a local copy, stopped the compiler with `internal: unresolved field 'length' reached lowering` — both pointing at code that was never wrong. An initializer the early pass cannot type — an empty list, a list whose elements share no common type, or a list holding calls or arithmetic — is typed by the ordinary body pass with the same diagnostics as before.
- An inherited field wins over a bound module's global that shares its name, in both reads and assignments, so a class member is the one you get.

### BASIC

- `ON ERROR GOTO <label>` works with every `RESUME` form. A procedure, method, or module body gets one error dispatcher, so the handler is installed exactly once on every path and a handler reached on a path that skipped its installation no longer fails verification. `RESUME` retries the failed statement, `RESUME NEXT` continues after it, and `RESUME <label>` jumps to the label; `RESUME` with no active handler raises "RESUME without error", and `ON ERROR GOTO 0` inside a running handler raises the handled error again. Loop and `SELECT CASE` state survives a resume into the middle of them. `END` inside a `SUB`, `FUNCTION`, or method ends the program instead of trapping.
- `STRING` and object values are managed. Every variable, parameter, field, function-name result, `USING` resource, and `FOR EACH` element owns one reference; assignment moves or retains and releases what it replaces, and every exit from a procedure releases what it holds. A runtime call's result follows its declared ownership, so a borrowed result is no longer released twice — `PRINT pat.Find(x).UnwrapStr()` used to trap with "invalid runtime string handle" — and an owned one is no longer leaked. `RETURN field` no longer frees data the object still owns, assigning to a `STRING` or object parameter no longer frees the caller's value, and temporaries in `IF`, `WHILE`, `DO`, `FOR`, and `SELECT CASE` headers are released once rather than on every pass of a nested loop.
- A `STRING` is never null. Constructors initialize every `STRING` field, including inherited ones, module and `STATIC` variables start as `""`, and an unset string array element reads as `""`.
- `STATIC` class members are shared. A static field lives once in module storage and is the same value through `Class.field`, `instance.field`, and the bare name; `STATIC SUB`, `FUNCTION`, and property members stay static; static constructors run in declaration order when the module initializes; and a `STATIC DESTRUCTOR` runs when the program ends normally, including through `END`. A bare class name works as a receiver, and `ME` inside a `STATIC SUB` is an error.
- `obj = NOTHING`, `obj <> NOTHING`, and `obj IS NOTHING` compile in either operand order, and comparing a non-object with `NOTHING` stays an error. `HEX$`, `OCT$`, `SPACE$`, and `STRING$` are built-ins with argument checks.
- Namespaces, interfaces, and scoping resolve correctly. Classes inside a `NAMESPACE` get a real layout instead of an 8-byte allocation, calls through an interface-typed variable reach the implementation instead of returning 0, `USING` inside a namespace and `USING X = Ns` aliases work for procedures and classes, a parameter shadows a module variable of the same name, and a receiver field shadows a module global inside class members.
- Types are checked where they were assumed. `RETURN` converts numeric results instead of producing invalid IL, a string/number mismatch reports B4010, a class-returning `FUNCTION` carries its class, assigning an object of an unrelated class reports B2001, an unknown `AS <Class>` reports B2111, `AS I64` and `AS F64` are primitive types, `DIM A(n)` bounds checks are inclusive, and `DOUBLE` array fields allocate floating-point storage.
- The B10xx diagnostic catalog matches what the analyzer reports: B1012 means `RESUME` without `ON ERROR GOTO` in the same procedure, B1003 names the missing label, and duplicate local declarations report the new B1013.

### Platform services

- `Zanna.Services` is a new, provider-neutral runtime library with preview stability. `Platform.Init(provider, appId)` returns a `Result`; `Platform` then reports `Status`, `UserId`, `UserName`, `Language`, `IsLicensed`, `IsOnline`, and `IsDlcInstalled`, and `Diagnostics()` keeps recent non-fatal problems. Before a successful `Init`, or when the provider library is absent, every member returns a neutral value, so one executable runs from Steam, from another store, and in CI.
- `Achievements` unlocks, clears, and describes achievements; `Stats` sets integer, floating-point, and average-rate stats and commits them with `Store()`; `Leaderboards` finds, creates, uploads to, and downloads up to 100 entries from a board addressed by name; `Presence` publishes rich presence keys; `Overlay` opens platform pages, web pages, and store pages and positions notifications; `OnScreenKeyboard` shows a floating keyboard or requests full-screen text entry; and `Cloud` reads, writes, and deletes cloud files. `Zanna.Services.Steam` carries Steam-only queries such as `HardwareType`, `IsUnderProton`, and `IsBigPicture`.
- Work that completes later returns a `Zanna.Services.Request` polled across frames rather than a future, because the result arrives through the same main-thread pump a blocking wait would stop. Platform callbacks become events in a 256-entry queue read with `PollEvent()`; overflow drops the oldest event and is counted. `Canvas.Poll` and `Canvas3D.Poll` pump the active provider, so a game with a canvas never calls `Update()` itself.
- The Steam provider opens `steam_api64.dll`, `libsteam_api.dylib`, or `libsteam_api.so` from beside the executable, or the path in `ZANNA_SERVICES_STEAM_LIBRARY`. It is written from Valve's public documentation against redistributables from SDK 1.61 through 1.65; the repository contains no Valve headers or binaries, and nothing from the SDK enters the build or the link. A missing function reports an incompatible library and names it, a missing interface disables only its features, and a callback whose size disagrees with the binding is dropped with a diagnostic instead of being decoded.
- The binding was checked against the real SDK. Every function it resolves exists in the Steamworks 1.61 redistributable or has a 1.61 fallback, every bound signature is identical in the 1.61 and 1.65 headers, and callback ids, structure layouts, and enumeration values are pinned by static assertions. A signed-in Steam client on macOS passes every check in `examples/apps/steam-check`, both from the interpreter and from a `steam-macos` package, including `Shutdown` followed by a second `Init`. That example prints PASS, FAIL, SKIP, or INFO for every services class and exits 1 on a failure; without Steam it checks that every member stays neutral. `Init` with no Steam client running now reports `ClientNotRunning`, while a running client with nobody signed in still reports `InitFailed`.
- `Platform.LaunchCommandLine` and `Platform.LaunchParameter(key)` read the values a `steam://run` link passes, so the `LaunchParametersChanged` event can be acted on. `Feature.LaunchParameters` reports support, an empty key traps, and a command line that fills the 4,096-byte buffer records a truncation diagnostic.
- `Zanna.Services.Timeline` marks Steam's background recording: instant and ranged events, the tooltip describing the current state, the game mode that colors the timeline, and phases with ids, tags, and attributes. Recording queries for an event or phase return a `Request` whose new `DetailCount` and `Detail(index)` give recorded time, longest clip, clip count, and screenshot count, and the overlay can be opened to a phase or event.
- `Platform.DlcCount`, `DlcIdAt`, `DlcNameAt`, and `DlcAvailableAt` list what a game sells, and `BuildId` and `BranchName` report which build and beta branch the player is running.
- `Achievements.IconWidth`, `IconHeight`, and `IconRgba` read the platform icon for an achievement's current state, and `EventKind.AchievementIconReady` arrives when a load finishes; an achievement with no icon is remembered for the session so a read-on-event loop cannot spin. `Achievements.RequestGlobalPercentages` and `GlobalPercent` report how many players unlocked each achievement; an app without global percentages completes the request as failed.
- `Zanna.Services.ActionInput` binds a Steam Input action manifest and exposes controllers and their types, action sets and layers, digital and analog action data, action labels, input origins with their labels and glyph paths, rumble, and LED color, with `ControllerConnected`, `ControllerDisconnected`, and `ControllerConfigured` events. Steam refuses a manifest until a controller has been used with the app, so the binding keeps Steam Input running and retries when a controller connects. Glyph paths use `/` outside Windows.
- `Zanna.Services.Workshop` and `WorkshopItem` cover subscribed and installed items, install and download state, queries by app, user, or explicit ids, subscribing and unsubscribing, downloading, creating an item, submitting an update with status and progress, and deleting, with the `WorkshopQuery`, `WorkshopList`, `WorkshopVisibility`, and `WorkshopUpdateStatus` enumerations, `Request.ItemCount` and `ItemAt`, and installed, downloaded, and subscription-changed events. The binding supports both Workshop interface versions the supported redistributables ship.
- `OnScreenKeyboard.RequestText`'s maximum length counts characters, as Steam does; the submitted `Value` length is still reported in bytes.

### Packaging and installers

- `zanna package --target steam-windows`, `steam-macos`, and `steam-linux` write a SteamPipe build root — `content/<platform>/`, an app build script, and a manifest with each file's size and SHA-256. A run replaces only its own platform, so packaging each OS into one root builds a multi-depot release, and content is staged beside the root and moved into place only after it verifies. New manifest directives `steam-app-id`, `steam-redist`, `steam-depot`, `steam-build-description`, and `steam-set-live`, and the `--steam-redist` option, describe the release. The executable and the redistributable are checked for a matching OS and CPU architecture, macOS builds merge the entitlements Steam requires and sign nested code before the bundle, `steam_appid.txt` is never shipped, and `steam-windows --arch arm64` is rejected because Valve ships no Windows arm64 redistributable.
- Every package format ships the project's asset packs where the runtime mounts them: `Contents/Resources` for macOS apps and disk images; beside the executable for Windows, tarballs, and Steam depots; and, for deb, rpm, and Linux bundles, `/usr/lib/<package>/` with a `/usr/bin` link to the executable when the project produces packs. A pack whose name collides with another payload file fails the build.
- A pack beside the executable is discovered on macOS and Linux. The check compared the last four characters of the file name against the five-character `.zpak`, so it never matched.
- Windows setup wears the product it installs. Its window captions, brand panel, and dialog icons were hardcoded to the Zanna toolchain, so an application package installed itself under the wordmark and icon of the compiler that built it. Package generation writes the project's `package-icon` into the package as a branding resource that sits beside the license and readme: setup reads it to brand its own windows and never installs it, so the installed file set and the reported install size are unchanged, and a package without one verifies and looks exactly as it did. Setup adopts the project's `package-name` as its display name as soon as the package metadata is verified; a failure raised before that point still names the toolchain rather than a product it has not confirmed.
- Linux bundles start again: `AppRun` is a launcher script, because the extractor rejects a symbolic-link entry point and every bundle failed before this. The bundle stub no longer leaves empty temporary directories behind.
- `--target dmg`, `rpm`, and `linux-bundle` compile on their own host instead of refusing, notarization archives use the right root for their entries, and packaging no longer leaves temporary binaries and packs in the system temporary directory.
- Windows installer creation no longer fails for payload layouts whose embedded offset previously oscillated during finalization.
- macOS disk images sign the app after it reaches its final location in the image, preserving a valid signature when the image filesystem normalizes a resource name.

### Windows

- Direct3D 11 no longer compiles its shaders when a program starts. A native Windows build of the runtime compiles the backend's 16 shaders once with a build-time tool and embeds the bytecode, which the backend uses whenever it matches the shader source linked into the program; otherwise it compiles at startup as before. Creating a `World3D` drops from 7.7–8.3 s to 0.19–0.23 s. Shaders now compile with IEEE strictness, so the `isnan()` guards on skinning, morphs, lighting, motion vectors, and temporal history survive compilation instead of being folded away.
- A Direct3D 11 frame no longer waits for the one before it. The swap chain asked for a single back buffer and never bounded frame latency, so the blit-model chain had nothing to hand back to the CPU after a present: the submitting thread blocked until the GPU finished, and every frame cost CPU time plus GPU time in series rather than the longer of the two. Two buffers and a maximum frame latency of two restore the pipelining, keeping the blit model on purpose so the cached render-target view survives a present. Direct3D was also the only backend that never implemented the presented-frame capture contract, copying the whole back buffer every frame — about 16 MB at 2560×1600 — for a readback most programs never ask for; it now snapshots only when a caller has declared that presented frames must stay readable. And the check that decides whether two adjacent opaque draws can be instanced together compares them in place instead of normalizing two 1.2 KB copies per pair, which at thousands of opaque draws was tens of megabytes of copying per frame. On one authored park on an RTX 4070 laptop, where the GPU had been about a third busy and one core of sixteen was working, the live scene moved from 9 frames a second to 26–43 and its shadow pass from 13.97 ms to 0.65–3.82 ms; the two samples framed different cameras, so the per-pass CPU times are the reliable comparison and the frame-rate ratio is indicative.
- A Windows graphical program started from Explorer, a shortcut, or an installer releases the console Windows gave it once its first window is shown, so only the program's window remains. It happens only when the program is the console's sole user: a program started from a terminal keeps printing to it, and output redirected to a file or pipe is untouched. Standard output from a desktop launch goes to `NUL`, and handles are replaced before the console is freed so a later write cannot land in an unrelated file. A lone Alt or F10 press no longer enters the modal window-menu loop that stopped the frame loop; the key events still arrive, and Alt+Space still opens the window menu.
- Native exception handling on Windows passes an explicit null frame to the C runtime's `setjmp`. The value it passed was unset, and Windows `longjmp` runs a structured unwind toward any non-null frame, so a trap could unwind instead of restoring the saved context. Running a native program reports its exact Windows exit code rather than a saturated value, so a program that returns -6 matches the interpreter.
- Direct3D 11 reserves shadow-atlas storage for the whole shadow budget. When general capacity rose from 12 slots to 20 earlier in this release, the Windows atlas still had room for 8 of the 16 non-cascade slots; it now covers all of them.

### Building Zanna from source

- On macOS and Linux the install step is its own script. `build_zanna_unix.sh` ran configure, build, tests, lint, audit, smoke, and install in one pass, so when the `sudo` prompt at the very end timed out while the tests were running, the only way to install was to run the whole build again. `scripts/install_zanna_unix.sh` — with `install_zanna_mac.sh` and `install_zanna_linux.sh` as platform wrappers — installs an already-configured build tree and never builds, failing immediately if the tree was never configured. It honors the same `ZANNA_BUILD_DIR` and `ZANNA_INSTALL_PREFIX` as the build driver, keeps the previous behavior for writable prefixes and non-interactive runs, and `ZANNA_SKIP_INSTALL=1` now names it for later. The per-build-directory lock is handed from the build to the install, so no other build can start between the two.
- Building from source on Windows works again. Four breakages had collected in code paths only Windows compiles — none of which the macOS and Linux gates could see — so the toolchain, Zanna Studio's native helper, and the test suite compile, link, and pass their checks with MSVC. The full Windows gate is green, and every bundled demo builds and passes its launch check. Two C-runtime conversion functions resolve to the Universal CRT in the native import planner, and the PowerShell build scripts no longer abort on a native tool's ordinary warning output: Windows PowerShell 5.1 turns a command's standard error into error records once the script's output is captured, so a CMake configure warning used to end a piped or logged `build_zanna_win.ps1` run before the build started. Each native step — configure, build, install, tests, and the lint, audit, and smoke stages, plus the CMake steps in `build_demos_win.ps1` — is now judged only by its exit code.

### Zanna Studio

- Project search runs on background file workers and publishes results as virtualized rows, so a search across a large workspace no longer freezes the editor while it works.
- A long-running build or test tool cannot fill memory with its own output: incremental stdout and stderr publication is capped, and the process's environment is captured when it starts rather than re-read later.
- When the file watcher cannot watch a directory it says so and falls back to polling, instead of silently missing external edits, and autosave, crash recovery, performance monitoring, and the debugger share one background budget so they do not compete with typing.
- Split editors replay small changes rather than copying and relaying the whole document after every keystroke, and language services follow the same edit history independently.
- Workspace-wide rename and replace operations retain a durable recovery journal until they complete. If a crash or power interruption occurs, the staged and replaced files can be identified and recovered; successful edits leave no journal behind.
- Save All reports the files it could not write instead of stopping quietly, a workspace index scan walks the whole workspace rather than stopping at its paging limit, and embedded play falls back safely in restricted macOS environments.
- Text in Studio and other GUI applications fills font outlines with TrueType's non-zero winding rule, so script and stroke-built faces whose contours overlap stay solid, and a contour built only from off-curve points — the usual encoding of an `o` or a bowl — is flattened instead of skipped.

### Documentation

Public references, command help, platform guidance, runtime API material, and language examples were reconciled with the current compiler and runtime behavior. The Game3D guidance now explains the single-window fullscreen coordinate contract and the separate responsibility of an application that chooses to letterbox a fixed design space inside a borrowed 3D window, and the canvas guide describes the 2D canvas's own centered letterbox and `Canvas.IsFullscreen`. The platform differences guide covers Windows desktop launches and the Alt and F10 keys, and the getting-started guide documents the separate install scripts and `ZANNA_INSTALL_PREFIX`.

A new platform services guide covers Zia and BASIC quick starts, every services class — timeline, app details, achievement icons, action input, and Workshop included — shipping with the Steam redistributable, the overlay and shutdown rules, testing without Steam, and adding a provider. The runtime class how-to teaches the current rules again — declared result ownership, definition fragments per area, required class summaries, and string-literal arguments through the literal cache — so code written from it compiles. The BASIC reference, grammar, namespace, and tutorial pages describe error resumption, managed values, and static members, and the error specification and errors chapter of the book follow the new diagnostic catalog.

### Known limitations

- This is a pre-alpha source release. APIs, diagnostics, IL rules, project formats, and tooling may change before a stable release.
- Native macOS support targets Apple Silicon. Linux targets x86-64 and AArch64; backend and platform capability details remain documented in the supported-platform guides.
- OpenGL point shadows, one Metal counter, and software-renderer reflection/HDR settings remain unavailable as documented in the 3D guides.
- MP3 frames that select the reserved Huffman codebooks 4 or 14 are rejected as unsupported data; standard encoders do not emit them.
- A `PostFX3D` chain can be attached to only one `Canvas3D` at a time. Projects that want the same post-processing on several active canvases need one chain per canvas; the second attachment is refused through `PostFX3D.LastError` rather than trapping.
- `RenderTarget3D.AsDisplayPixels` needs a frame that ended on a canvas with a usable post-processing chain. A target rendered without one returns the same scene-referred bytes as `AsPixels`.
- In a fullscreen single-window game, the adopted 3D canvas reports the window's public extent rather than the 2D canvas's designed size. Fitting a fixed design space inside that extent, and any letterboxing it implies, is the application's responsibility; the 2D canvas's own centered letterbox is withheld while the window is borrowed.
- `Canvas.IsFullscreen()` reports the window's real mode, which on macOS and X11 reaches a requested change over the following frames rather than immediately.
- `Camera3D.WorldToScreen` screen coordinates are bounded only when the visibility result is 1. A caller that ignores the flag still gets finite values for a point inside the near plane, but they do not describe a place on the screen.
- Build-time Direct3D 11 shaders are produced only by native Windows builds whose host and target processors match. Cross-compiled and cross-architecture Windows builds compile shaders at startup, with the previous delay.
- The Direct3D 11 frame-rate figures above were measured on one authored scene on one laptop. They are reported as evidence that the serial stall is gone, not as a general speedup factor.
- A Windows graphical program started from the desktop shows its console until its first window appears, and its standard output goes to `NUL` from then on. Run it from a terminal, or redirect its output, to keep what it prints.
- The expanded shadow capacity, the secondary shadow atlas resolution, and instanced shadow submission are verified on native Metal and the software renderer. Acceptance on native OpenGL and Direct3D 11 is still pending.
- `Canvas3D.SetShadowAtlasResolution` changes the size of secondary shadow tiles; it does not raise the backend's shadow-slot capacity.
- The blend tree state capacity change alters the size of an internal runtime object. A project must link against the rebuilt runtime from this release rather than mixing it with an earlier build.
- Signed floating-point motion vectors require a floating-point scene target. On OpenGL without one, the previous offset encoding is retained, and temporal results there remain as they were.
- `Canvas3D.NoteCameraCut` is verified on native Metal. The Direct3D 11 and OpenGL implementations are in place but their acceptance is still pending, and the software renderer takes only the motion and flare part of the hint.
- `Zanna.Services` has preview stability, and Steam is its only provider. Zanna does not distribute Valve's redistributable; a game ships its own copy under Valve's terms. Steam services are unavailable on Windows arm64, where Valve ships no library. The signed-in client check was run on macOS; Windows and Linux are covered by the fake-library tests. Steam Input accepts an action manifest only after a controller has been used with the app, so action data stays empty until then.
- Platform services never shut down automatically, because native Windows executables do not run exit handlers. Call `Platform.Shutdown()` before the program exits. Steam's desktop overlay draws only over GPU-presented `Canvas3D` and `World3D` windows, not the 2D `Canvas` or GUI applications, and may not attach when such a window was created before `Platform.Init`; `Diagnostics()` records that case.
- A program that defines a function named like one in the C or POSIX libraries now carries it under a `zn_`-prefixed symbol in a native build, which is the name a profiler, debugger, or symbol listing shows.
- Runtime results that used to be guessed into a specific class now declare the class they actually return, and a value declared `Zanna.Core.Object` needs an explicit `as` before it is used as a specific class. Code that relied on a guessed class — correct or not — may need that narrowing.
- The interpreter still keeps one extra string reference in a few patterns that native code releases — a borrowed copy such as `t = u`, a retained parameter, and a string held only by a slot at exit — so an interpreted BASIC or Zia program can retain more string memory than its native build. Aligning the interpreter with the native ownership convention is separate work.
