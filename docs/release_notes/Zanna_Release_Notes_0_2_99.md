# Zanna Compiler Platform — Release Notes

> **Development Status:** Pre-Alpha. Zanna is under active development and not ready for production use.

## Version 0.2.99 — Pre-Alpha (DRAFT — unreleased)

<!-- DRAFT: release date TBD. v0.2.7 was cut on 2026-06-30. -->

### What this release is about

Viper is now **Zanna**. The rename reaches everything you type: the CLI is `zanna`, programs bind `Zanna.*`, projects save as `.zap`, asset archives as `.zpak`, and the code lives at github.com/zannagames/zanna. ZannaIDE became **Zanna Studio**, and it moves your old settings over for you the first time you open it.

Past the rename, most of the effort went into making Zanna nicer to build on. The runtime's public API now uses one set of naming rules and one way of reporting failure, so a method behaves the way you'd guess and tells you when something goes wrong instead of handing back a mystery value. The 3D side outgrew being a plain renderer and became a game engine. Zanna Studio and the GUI toolkit were both rebuilt underneath, and Studio grew visual 2D and 3D scene editors, so building a level is now something you do by dragging objects around rather than by hand-editing a scene file. Underneath all of it, correctness audits went looking for the places the stack breaks under bad input, heavy load, or many threads.

By the end of the release those editors stopped showing you markers in a gray void and started showing you the level. Your project tells Studio, in a few lines of checked-in configuration, what its sprites, models, surface materials, backgrounds, terrain, sky, water, and color grade look like, and the editor reproduces them without ever running your game. Two whole demo games were rebuilt on that path to prove it works, loading their levels from authored scene files instead of level-builder code — and then those games, and the rest of the large demos, moved to a repository of their own, so installing Zanna no longer means installing a games library alongside it.

#### Highlights

- **One naming convention, one way to fail.** Collection sizes read as `Count`, string lengths as `Length`, and abbreviations are spelled out; the operations that can fail hand back an `Option` or a `Result` instead of a null or a `-1`. The old names stay as aliases, so nothing you've written stops compiling.
- **3D grew into a game engine.** First- and third-person runtimes — view-model rendering, spring-arm camera, character movement, combat, cloth, behavior trees, quests, world persistence — on top of image-based lighting, clustered lights, screen-space reflections, and temporal AA that work identically on all four backends.
- **Real fonts in a 3D frame (new).** `Canvas3D` draws and measures text through a `.ttf` face you load or a built-in default, with kerning and glyph bearings, so a HUD, a scoreboard, or a nameplate uses your game's typeface at any size instead of the fixed bitmap font.
- **The importer reads whole scenes (new).** Tiled maps and FBX arrive with their cameras, lights, rigs, and animation intact, and an offline `zanna asset` pipeline conditions all of it at build time rather than at load. A character rig keeps its skeleton hierarchy now instead of importing flattened.
- **Zanna Studio edits scenes (new).** Visual 2D and 3D editors with a nested object hierarchy, typed gameplay fields, tile tools that work like an image editor, a perspective viewport you fly through, terrain sculpting, prefabs, and undo on everything. `.scene2d` and `.scene3d` are the canonical extensions; your existing files keep opening as permanent aliases.
- **The editor frame is the game frame (new).** Declarative rules in your project's `scene-components.json` let Studio draw a spawn marker as the enemy it becomes, sit a 2D scene on your game's own background art, and surround a 3D scene with the terrain, water, sky, and color grade your game builds at runtime — then Game View drops the chrome and composes at your game's output size.
- **Your game runs inside the editor, on all three platforms (new).** Press Play and Studio builds if it needs to, launches, and shows the running game's frames in the scene viewport while the editor keeps working around it.
- **Scenes can be the source of truth (new).** A 2D campaign's ten regions and a 3D campaign's nine missions moved out of thousands of lines of level-builder code into authored scene files, with parity tools proving each rebuilt game reproduces the code-built original exactly.
- **Studio and the GUI toolkit were rebuilt underneath.** Multiple roots, split panes, crash recovery, a full VT terminal, background git, and a debugger that opens objects into named fields; scalable themes, Unicode grapheme editing with IME, native screen readers, and virtualized lists and trees. The toolkit's public API didn't change, so your GUI code keeps working.
- **A batch of things you can feel.** A sustained 3D fight stops losing frame rate, a ragdoll falls like a body, a car drives on a moving platform, a bake covers the whole level instead of half of it, a killed enemy stays dead, a patrol walks at the speed you set, a HUD panel is translucent on every backend, Metal scenes have their shadows back, and a bat or a glove attaches to the hand that's holding it.
- **The stack was audited for bad input, heavy load, and many threads.** Runtime, IL, the Zia frontend, 2D and 3D graphics, gameplay, animation, navigation, physics, spatial audio, post-processing, world and timeline state, Windows, and Linux. One theme runs through all of it: a handle that isn't live is refused rather than dereferenced, and a partial result is discarded rather than published — so a driver hiccup or a hostile asset costs you a frame, not the session.
- **Real installers everywhere.** A native Windows toolchain installer with rollback and repair — branded, keyboard-accessible, and sharp at any DPI — plus AppImage, RPM, DMG, and Windows packages for standalone apps, each one checked, checksummed, and manifested before it ships.
- **Native Wayland on Linux (new), and Windows paths that used to fail.** Wayland is chosen automatically with an X11 fallback and no external dependencies. On Windows, a project under `C:\Users\Ольга\Проекты` — or nested past the old `MAX_PATH` ceiling — compiles, packages, installs, and runs.
- **Generated code runs faster, and Zia gained list combinators.** Dense `switch` statements become jump tables, narrow overflow checks use the CPU's flag bits, and provably unnecessary checks are dropped; `map`, `filter`, `reduce`, and friends lower to plain loops with no closures and no allocation.
- **The showcase games moved to their own repository.** Cloning, building, and installing Zanna no longer drags a large examples tree along with the compiler. `examples/` keeps a curated set you can read in an afternoon; the big games live at github.com/zannagames/zannademos and still run as a full suite when you clone them alongside.

### Runtime public API and contract

- One name per symbol. Collection sizes read as `Count`, semantic lengths as `Length`, boolean checks return true or false, and short abbreviations are written out (`LeadZ` → `CountLeadingZeros`). The old names stay as aliases, so existing code compiles unchanged.
- Recoverable failures return something you can branch on. Terminal reads, collection and channel pops, decryption, HTTP/REST/SMTP sends, parsing, searches, shell commands, and 3D queries all gained `Option`/`Result` forms, so error handling becomes ordinary control flow instead of null checks and sentinel comparisons.
- The dangerous parts are labeled as such. Manual memory, trap-state changes, and legacy ciphers moved into clearly named `Runtime.Unsafe` and `Crypto.Legacy` homes, so nothing risky sits behind a harmless-looking name.
- The runtime's documentation reaches you where you work: editor completion and hover, the LSP and MCP servers, and `zanna --dump-runtime-api`, which also records each 3D binding's ownership, nullability, and whether it can fail.
- Types that were vague are specific. `Pixels.ToBytes()` and `Pixels.FromBytes(...)` declare `Bytes` instead of a bare object, so a `ToBytes()` result infers as `Bytes` in the type checker and in editor completion — chaining a `Bytes` member off it type-checks now instead of being read back as another `Pixels`. `Camera3D.WorldToScreen(...)` declares the `Vec3` it has always returned, so `.X` and `.Y` read straight off the result, and `SceneTemplate.Instantiate`/`InstantiateSceneAt` declare `Entity3D`, so you can call entity members on what you just spawned.
- A property you can read is a property you can assign. Assigning to a runtime property resolves its setter by name, and seven registered setters had drifted off that convention — so `music.Volume = 62` failed to compile with an "unsupported assignment target" error even though the property was right there, and five `Game.UI` HUD text-input properties plus its font were write-blocked the same way. Every setter in the runtime was audited against its property and the drifted ones renamed; nothing called the old spellings, so this turns dead names into working ones rather than breaking code. One gap is left and written down: `GpuTexture2D` borrows `Texture2D`'s `Filter` and `Wrap` accessors, so assigning those through a `GpuTexture2D` still misses.
- Recoloring a texture by its brightness is one native call. `Pixels.TintLuminanceMasked(rgb, strength, lumLo, lumHi)` tints a buffer toward a color with a per-pixel luminance ramp — dark detail below `lumLo` untouched, bright fabric at `lumHi` and above taking the full tint — in place, with alpha preserved. It replaces the per-pixel scripting loop that team-coloring a 2048² character texture used to require.
- Anything the 3D runtime holds, you can read back. `Quat.ToEuler` and `Quat.FromMat4` invert `FromEuler` and `ToMat4` exactly, `Camera3D` reports its view and projection matrices, aspect ratio, and up vector, and read peers arrived for texture-atlas rects, instance-batch transforms, meshes, and materials, skeleton bone parents and bind poses, `Transform3D` Euler angles, every retained `Terrain3D` and `Water3D` setter including hole enumeration, and the three properties that were write-only (`Canvas3D.Wireframe`, `Particles3D.Additive`, `Path3D.Looping`). `SceneNode.TrySetWorldPosition` moves a node in world space and rejects the edit outright when the parent transform can't be inverted, and `Vec2.X`/`Y` are writable like `Vec3`'s.
- The 3D surface stopped hiding parts of itself. `Gltf` now exposes the scene, node, camera, animation, and skeleton accessors its loader always implemented, matching `Fbx`, and `Ray3D`, `AABB3D`, `Sphere3D`, `Segment3D`, and `Capsule3D` are registered as classes, so they appear in hover, completion, and `--dump-runtime-api` — Graphics3D lists 70 classes and 1,301 members. Everything in these two bullets is an addition: no existing binding changed its signature or its meaning, and the flat function names still work.

### 3D rendering

#### What the renderer draws

- Image-based lighting, a clustered forward+ light path, screen-space reflections, soft particles, and temporal anti-aliasing all land on Metal, OpenGL, D3D11, and the software backend, so a scene looks the same wherever it renders.
- The GPU backends use reversed-Z float depth, which puts precision in the distance and stops the z-fighting and shimmer you'd get across a wide open-world clip range. The software backend keeps standard depth as the deterministic reference.
- Occlusion culling rasterizes real triangles instead of bounding boxes, so a near wall or a rotated object actually hides what's behind it. That means fewer wasted draws in crowded scenes.
- Frame pacing steadied over long sessions. GPU backends sync to the display instead of a redundant CPU limiter, on-screen text reuses its rasterized glyphs rather than re-uploading them each frame, and Metal no longer stalls the CPU while streaming textures in, so the periodic hitching is gone.
- Shadows are back on Metal. The shadow comparison sampled depth in OpenGL's clip range while the depth pass wrote `[0,1]`, so every shadow test failed and a native macOS scene rendered flat and unshadowed. The comparison remaps to the range actually written now. Alongside it, a material you declared opaque stays opaque: an explicit alpha mode wins over the automatic texture-alpha classification, so an imported opaque surface casts its shadow instead of being auto-promoted to blended and dropping out of the shadow pass.
- On Windows, the D3D11 backend clamps every shader constant buffer before upload and supports the full BC compressed-texture family, which closes a batch of driver-specific glitches.

#### Off-screen rendering, picking, and profiling

- New things you can query: why a backend fell back, how many draws were dropped, mesh memory budgets. `TrySet…` setters and accurate `BackendSupports` probes let you ask whether a capability exists instead of trapping when it doesn't.
- Those counters now count on Windows. `BackendDrawCalls`, `BackendDroppedDraws`, the mesh-cache hit and miss pair, `BackendStreamUploads`, and the present-path classification are wired into the D3D11 draw and present paths through saturating counters, so a profiling overlay or a CI budget check reads real numbers on Windows rather than a row of zeros. Metal reports the same set apart from texture-fallback binds, and the software backend reports zeros by design — both written down in the platform-differences table rather than left for you to discover.
- `Canvas3D` renders without a window, into a `RenderTarget3D` you own and read back. That makes offscreen 3D — asset thumbnails, editor viewports embedded in a GUI, headless image generation — something you can write directly, and it's what Studio's own 3D viewport is built on. A second constructor asks for the platform GPU backend and tells you truthfully which one it got: on macOS that's a real windowless Metal context, while Windows and Linux report the software fallback until their headless paths are finished. The original constructor still gives you the deterministic software rasterizer when you want reproducible pixels.
- A 3D world can render inside the window you already have. `World3D.WithCanvasCamera(canvas, fov, near, far)` — with `Canvas3D.NewOnCanvas(canvas)` underneath — attaches the 3D renderer to an existing 2D `Canvas` window instead of opening a second one, so a game whose menus draw in 2D and whose gameplay runs in 3D lives in one window like any commercial title, fullscreen included. The window is borrowed rather than owned: when the world goes away, presentation returns to the 2D canvas and your menu keeps painting in the same window. All of it works through the existing backend surface — no platform-specific code, on all three platforms. The loan is returned the moment the 3D world is destroyed rather than whenever finalization happens to run, so a 2D shell that hands the window to a 3D game and takes it back — repeatedly, in one session — never waits on the collector to get its window working again.
- The scene graph can be picked triangle-accurately. Alongside the bounding-box raycast, `RaycastNodesPrecise`, `RaycastNodesPreciseAll`, and `RaycastPreciseHit` answer "which mesh is actually under this ray" — nearest node, every node front to back, or the hit point, normal, and triangle itself. Cheap broadphase stays cheap: candidates are box-filtered first, then tested against a cached triangle tree. Use it for editor picking, spawn-at-cursor, and surface queries; keep the box query where approximate is the point.
- A mesh will tell you where its vertices are. `Mesh3D.VertexPosition(index)` returns an owned `Vec3` for any vertex, or null for an index that isn't there, so a tool can snap to real geometry instead of guessing from a bounding box. It's what Studio's vertex snapping is built on, and it works from your own code the same way.
- A 3D frame can carry real text. `Zanna.Graphics.TtfFont` loads a `.ttf` face from disk or falls back to an embedded default, reports its family and its scaled width, ascent, and line height, and `Canvas3D.DrawText2DTtf` and `MeasureText2DTtf` draw and measure with it — UTF-8 decoded, kerned, and positioned by each glyph's own bearings. A scoreboard, a nameplate, or a HUD label uses your game's typeface at whatever size the layout asks for instead of the fixed bitmap font, and repeated draws of unchanged text reuse their cached raster rather than re-rasterizing every frame. The font releases its face on collection, so loading one per screen doesn't leak.
- A software-backend screenshot now matches what was on screen. Capturing a frame after it presented — or presenting the same frame twice — re-ran the CPU finalization chain on pixels that were already display-encoded, double-applying gamma and washing every capture toward gray. Finalization now runs exactly once per rendered frame, so `CaptureFinalFrame` and repeated presents return the same bytes the window showed, and the software demos' screenshots stop looking fog-washed next to their Metal twins.
- Metal can be read back after it presents, if you ask it to. A direct present hands its drawable to the display and keeps nothing readable, so a capture taken after the frame was shown came back empty on the native backend. `Canvas3D.SetCaptureAfterPresent` turns on a copy into a readable display texture before the present goes out — enough for screenshot tooling and automated capture — while the default path stays the zero-copy present it has always been.
- A post-processing chain can be inspected and edited in place. `PostFX3D.GetEffectKind(i)` enumerates the chain in application order against the new `PostFXEffectKind` constants, and `RemoveEffectAt(i)` deletes one entry without rebuilding the rest — what an effects editor needs instead of `Clear()` and re-add. Nav agents grew the pause idiom and path readback: `Stop()`/`Resume()`/`IsStopped` hold an agent in place while keeping its target, path, and `RemainingDistance` live, and `Target`, `HasTarget`, `PathCornerCount`, and `GetPathCorner(i)` expose where it's going and the exact corners it will walk — enough to debug-draw a route or preview a patrol without shadow bookkeeping.
- Post-processing grades the picture on the software path too. The CPU effect path builds one packed `RGBRGB…` float frame, but the scene-aware effects walked it as three separate channel planes — so SSAO, depth of field, motion blur, screen-space reflections, auto exposure, color LUT grading, sun shafts, and temporal AA each moved color between unrelated pixels instead of grading the pixel in front of them. All eight address packed pixels now, the render target's alpha is carried through untouched rather than overwritten by color work, and temporal AA snapshots the frame before it resolves so its neighborhood clamp reads original pixels regardless of traversal order. That is the path a software-backend game and an offscreen `RenderTarget3D` render through, so a graded scene looks graded there instead of smeared. Auto exposure, color LUT, and sun shafts also stopped vanishing from the ordered chain handed to the GPU backends, and `Clear()`, add, and remove reset the temporal history and eye adaptation, so a chain you rebuild can't blend against the shape it used to have. Between frames the chain keeps its buffers and the display-gamma table is built once per process, so an effect stack that runs every frame stops churning allocations.
- A Studio-authored scene becomes solid with one call. `PhysicsWorld3D.BuildSceneColliders(scene)` materializes the collider convention Studio's inspector writes — box, sphere, capsule, and mesh-bounds shapes plus trigger flags — into static bodies at each node's world pose, replacing the per-game metadata parsing every scene-driven demo used to hand-roll. And the clips an imported rig carries stopped being invisible: `SceneGraph.AnimationCount`, `GetAnimationName(i)`, and `GetAnimationDuration(i)` enumerate the baked clip carrier, with `GetAnimation(i)` handing back rigid-node clips ready for `NodeAnimator3D`.

#### Baked lighting and probes

- A bake covers the whole scene or fails out loud. `LightBaker3D` used to stop descending after 512 nodes and bake whatever it had reached, so a large level came out partly unlit with nothing to tell you why; it now walks up to 65,536 nodes and fails the gather rather than publishing a partial scene. Everything a bake depends on — texel density, sample and bounce counts, sky radiance, the light list — freezes when the first gather starts, so a chunked bake stays internally consistent even if the scene changes under it. Charts are capacity-checked before any sampling, so an atlas that overflows fails the bake instead of leaving half a page written and half the UVs published, and `Apply` stages every material instance before replacing one, which makes it atomic and safe to call twice.
- A baked scene matches the preview it came from. Baked punctual lights now honor the same range fade, distance decay, spot inner/outer falloff, and `CastsShadows` flag the realtime path uses, so switching a light from realtime to baked stops changing how the room looks. Authored normals transform through a scale-safe inverse transpose, so mirrored and non-uniformly scaled meshes light correctly instead of turning inside out.
- Probe grids are portable files now. `.vlpg` writes fixed-width little-endian integers and IEEE floats rather than whatever your machine's memory happened to look like, so a grid baked on one machine loads on another. Load validates dimensions, finiteness, and length and swaps the parsed payload in only after the whole file reads cleanly, so a truncated or malformed grid leaves the one you already had bit-for-bit intact. Sampling renormalizes over the valid probes around a point, returns black for an unbaked grid instead of noise, and probes buried inside geometry fill from the nearest valid region.

#### Holding together under load

- An audit of all four backends made GPU resource replacement transactional. A texture, cubemap face, mip chain, or buffer that fails to allocate, upload, or synchronize now leaves the previous complete resource on screen instead of publishing half of one, and an upload that has already failed for good stops being retried every frame. Metal keeps a cluster buffer immutable while the frame using it is still in flight and only ever hands out a complete active or fallback texture; D3D11 reports device loss instead of drawing through it; OpenGL validates cubemap faces against the live context limit and restores the scissor state it borrowed; and the software rasterizer keeps additive fragments additive at full alpha, checks its stride arithmetic, and reuses its rasterization scratch instead of freeing and regrowing it after every draw. So a driver hiccup or an oversized asset costs you a frame, not the render.
- Overlay transparency composites correctly everywhere. Screen-space overlay geometry took its blend classification from the wrong command, which made a translucent overlay an opaque scrim on the GPU backends and darkened in-frame overlay alpha twice on all four. Vertex alpha is the single opacity source now, so a HUD panel, a screen fade, or a vignette matches across Metal, OpenGL, D3D11, and the software renderer. A newly created light also starts on the same canonical emitter basis the scene loader normalizes to, so save, load, save comes back byte-identical.
- The stateful 3D systems came through a 99-finding audit of their own — reflection probes, sky, and time of day here, ragdolls and vehicles under Physics below. A reflection probe validates and restores your render target before it publishes a cubemap, and keeps its dirty flag through a failed capture so the next frame retries instead of leaving a stale reflection on the wall. Sky and time-of-day repair corrupt state, survive absurd time deltas, and regenerate faces only when something actually changed. A texture atlas keeps its region IDs stable across a rebuild, verifies its backing store rather than trusting it, and fills rows with checked block copies instead of a per-pixel call, so packing a large atlas costs noticeably less.
- A canvas that has been rendering for hours behaves like one that just started. A closing integrity pass gave `Canvas3D` single ownership of its scratch buffers, retained objects, and overlay collections, and made its per-frame arena refuse wrapped alignment, bad bump offsets, foreign pointers, and cyclic chunk chains rather than trusting them. The motion history that drives temporal effects keeps every entry across a growth, stays finite and alias-safe, and rolls a failed insert back; the frame serial rebases before it can overflow and invalidates every cache keyed to it at the boundary, so a marathon session can't start serving stale frames. Particle sort buffers and their overflow slots publish atomically, so a sort that can't allocate leaves the last complete draw rather than a half-built one. And software-backend cubemap sampling validates all six faces once per sample and then reuses one borrowed view across the nearest, bilinear, wrapped, and roughness taps instead of re-acquiring per tap — noticeably less lock traffic in reflective software scenes.
- An effect chain can be rebuilt all session without accumulating damage. A 100-finding pass gave `PostFX3D` and the snapshot it hands the GPU backends a single authoritative owner for their storage: a chain that has been corrupted, or a by-value copy that only borrowed the allocation, detaches rather than resizing or freeing memory it doesn't own, and every retained effect parameter — bloom threshold and intensity, tone-map mode and exposure, FXAA thresholds, brightness, contrast, saturation, vignette radius and softness — is re-normalized before it can reach a kernel. Chains are capped at 4,096 entries on both sides, an unknown effect kind is dropped instead of dispatched, and removing the last LUT entry releases the image it was holding. The appended ownership metadata is a C ABI change, recorded in ADR 0245.
- The model, overlay, and decode paths came through a 50-finding pass of their own. Generating LODs collects the whole model first — every scene root, no repeats, cycles terminated — before it changes anything, requires each level to genuinely reduce its triangle count, and releases what it built when a step fails instead of reporting partial success. Overlay text and debug geometry share one bounded path, so a draw or a measure stops on a whole UTF-8 character rather than splitting one, and raster sizes, image regions, nine-slice arithmetic, projections, and crosshair geometry are checked before anything is allocated or submitted. BC6H HDR textures fail closed on malformed field layouts and impossible mip counts rather than decoding garbage, and GPU frame readback is bound to the storage that actually owns it.

### 3D assets, animation, and the asset pipeline

#### Import

- The importer decodes Draco, meshopt, and Basis Universal compressed glTF, quantized attributes, and KTX2 textures, so assets exported from standard tools load directly. A malformed stream fails with a named error instead of crashing.
- Compressed geometry is checked before it is trusted. The Draco decoder's byte, varint, rANS, topology, prediction, transform, and allocation paths were hardened against narrowing, overflow, malformed metadata, non-finite output, and out-of-range indices, so a truncated or hostile compressed mesh reports a named error instead of producing garbage geometry or taking the process down.
- FBX import is thorough now. A file authored in a DCC tool arrives with its meshes, skeletons and skinning, NURBS and patch surfaces, layered and constraint-driven animation, node-coupled cameras, lights, and blend shapes — binary or ASCII, through one evaluator. You get the scene, not just the geometry.
- A character rig keeps its hierarchy through import. A bone's connection list holds more than its parent: exporters attach the same object to display layers, groups, deformer links, and constraints, and a character rig links every core bone as `SpineLink`, `FootLink`, and the rest ahead of its real parent. Taking the first connection therefore made a constraint the bone's parent and silently flattened the imported skeleton. The lookup now walks the whole chain and accepts only a link to the scene root or to another `Model` node, and every consumer of it — skeleton extraction, the scene root, node animation, the constraint tables, and the constraint static pose — agrees on the answer.
- A big capture package imports at a sane cost. A pose is now evaluated once per animation stack per tick and shared between constraint and node-animation extraction, instead of once per bone; key-time scratch is one reusable buffer per stack rather than a fresh growing array for every bone, which is what let a 218-stack package exhaust the import budget on scratch alone; and a file whose only constraint is an unevaluated rig definition — the shape most mocap exporters ship — no longer pays whole-pose constraint evaluation for every bone. Unknown and inactive constraints are still preserved for diagnostics; they simply can't change a pose.
- Tiled maps load directly. `SceneDocument` and `TiledMapLoader` read finite or infinite Tiled JSON (`.tmj`) and TMX (`.tmx`) into an editable scene or a render-ready tilemap in orthogonal, isometric, staggered, hexagonal, or oblique projection. Tilesets, transforms, parallax, tint, collision, typed metadata, and animation all survive a save and reload.
- Loading a scene tells you what it couldn't resolve. `SceneGraph.LoadResult` and `LoadTextResult` hand back a failed load as a value instead of trapping — the inverse of `SaveToText` — `AdoptAnimations` appends another scene's clips to the one you already have, and `UnresolvedPrefabCount` plus one `AssetDiagnostics3D` warning per placeholder name the node, the portable path, and why the prefab didn't arrive: missing, cycle, depth, budget, or invalid. A placement that used to fail quietly is now something you can see and fix; how prefabs resolve didn't change.
- A hardening pass makes asset parsing strict and all-or-nothing, and keeps rendering, physics, navigation, terrain, and particles bounded and recoverable. A bad asset or an overloaded scene degrades in a defined way rather than crashing, and mesh and ray data that never changes is cached instead of rebuilt each frame.
- A model that won't fit loads nothing rather than something. Growing a glTF file's mesh, material, and variant tables is one transaction with its capacity and byte-product arithmetic checked up front and its replacement storage zero-initialized, so an oversized or hostile model fails the load instead of publishing a partly grown table. On the way back out, a scene's packed float data is bounds-checked element by element and Base64 is emitted strictly, so a `.scene3d` you save is a `.scene3d` any Zanna reads.

#### The `zanna asset` pipeline

- `zanna asset bake` keeps the whole scene, not just its geometry: every scene, camera and its animation, light, skeletal and morph clip, and material variant, plus the exact source bytes of your KTX2/PNG/JPEG/GIF/BMP textures. A per-slot report tells you which textures were kept untouched and which had to be re-encoded.
- A bake can shed weight it doesn't need. `--simplify-meshes N` decimates every mesh above N triangles down to the budget at bake time, so a million-triangle prop pays its simplification cost once on the build machine instead of at every launch, and `--strip-meshes` drops meshes and materials entirely for animation-only bakes — a captured clip library keeps its nodes, skeletons, and clips and loses the mesh payload that no one was loading it for.
- You can bake part of a package. `zanna asset bake --clips LIST` keeps only the clips you select — clip names, zero-based skeletal-clip indices, or inclusive `A-B` ranges — with node animations following matching names, since exporters emit paired skeletal and node clips under one stack name. A selection that isn't ascending or runs out of range is rejected with the model left completely unchanged. That is the answer for a capture package too large for a single VSCN document: ship it as the takes your game actually plays.
- A bake can shrink its textures instead of choking on them. `zanna asset bake --max-texture-dim N` replaces any shared material texture wider or taller than N with a compact raw-pixel payload, so a model authored against 4K source art bakes into a document your game can load without you re-exporting the art. The guarded document ceiling moved to 512 MiB alongside it, which is what lets a full-mesh, texture-limited bake of a large scene through while still catching a runaway one.
- A failed bake tells you which step failed. Every VSCN save failure now records a diagnostic — the document size limit (with a hint to use `--clips`), the temporary file, a partial write, flush and sync, the atomic replace, inventory validation, and document serialization — and it reaches both the plain-text output and a `message` field in the v1 JSON report. The save path used to return zero from every failure with nothing to say, so a failed bake printed `stage: "save"` and left you guessing.
- Materials cover the full PBR set — clearcoat, sheen, anisotropy, transmission, volume — with signed and unsigned BC6H HDR textures, on all four backends.
- Animation scales up: skeletons to 1,024 bones, up to eight influences per vertex with GPU skinning, cubic-spline tangents, and tolerance-based clip compression. `GenerateLODs` builds LOD chains for you, and `AssetDiagnostics3D.GetImportReport` reports in JSON what an import skipped or truncated.

#### Animation, rigs, and navigation

- `Animation3D.Retarget` solves the pose instead of copying keys. Driving a T-pose auto-rig from an A-pose capture used to carry the constant difference between the two rest poses into every frame — arms elevated most of a right angle, hands a foot and a half above where the capture put them — because retargeting copied each channel across and tried to compensate with a fixed rest delta. It composes the source pose at each key time now and solves the destination hierarchy parent-first, aiming every bone at the direction its source counterpart points, so a difference in bind convention cancels by construction rather than being subtracted afterwards. Two source bones that map onto one destination bone — a Biped's root and its pelvis both landing on a glTF `Hips` — compose into one channel instead of one of them silently winning, which is what used to discard the hip rotation that drives a swing or a pitch. Bone matching got stricter to go with it — a `Bip01 L Hand` reads its side letter before its role, and two rigs with different bone counts no longer pair off whatever is left over by list position. Rigs whose rests already agree get the source pose exactly, twist included.
- A capture becomes the clips your game actually plays. `Animation3D.StripRootMotion(boneIndex, keepVertical)` pins a root channel's travel to its first key, so a clip carrying real ground travel plays in place while your gameplay code owns where the actor is — `keepVertical` leaves height free for crouches and slides. `ExtractRange` lifts an immutable, time-rebased slice out of a longer take, so one captured session becomes a windup, a swing, and a follow-through rather than one clip you have to scrub.
- One captured swing covers both sides. `Animation3D.Mirror(animation, skeleton)` returns an immutable left/right-mirrored copy of a skeletal clip: every local key reflects across the rig's model-space centerline, cubic tangent lanes included, and channels swap onto their exact `Left`/`Right` name partners, falling back to humanoid roles when the names don't pair. Center bones stay themselves, timing, duration, and looping carry over, and mirroring twice returns what you started with — so a right-handed capture supplies the left-handed animation instead of being shot twice.
- An attachment lands in the hand that's holding it. A skinned parent node's world scale wasn't applied to the bone-space socket pose, so a rig authored in centimetres — what a capture pipeline usually hands you — put a counter-scaled bat, glove, or weapon somewhere near the character rather than in its grip. The socket pose is scaled before rotation and translation now.
- Animation playback stays sane at the edges. A 163-finding audit gave skeletons, clips, keyframes, blend buffers, and player palettes outright ownership of their storage, so an allocation that fails can't publish a half-grown channel table or destroy the configuration you already had. Looping, one-shot, crossfade, and blend clocks are bounded under extreme elapsed time and playback speed, an outgoing fade keeps advancing after its target stops rather than freezing mid-blend, a clip that becomes invalid restores the bind pose, and quaternion and matrix math runs through scaled double-precision intermediates so large-but-valid values don't collapse. Repeating an assignment that changes nothing no longer bumps a revision, so idle rigs stop churning. Saving and loading a rig is strict in both directions: key times, masks, lanes, tangents, rotations, and channel indexes must be exact finite numbers and unique, bones come back through the ordinary insertion path with their names byte-for-byte intact, and the wire structs are zero-initialized, so the same scene saves to the same bytes on every machine.
- Skinning and cloth cost less and fail cleanly. GPU skinning derives its palette bounds from validated skeleton and mesh data, normalizes oversized influences before narrowing to float, and counts only the draws and bytes actually queued; crowd palette scratch moved into the frame arena, so a crowd of skinned characters allocates less per frame. Cloth bounds gravity, wind, dimensions, and point counts, catches a fixed-step sim up over at most eight substeps while keeping the remainder instead of trying to close an unbounded gap in one frame, refuses an oversized or branched bone chain without damaging the binding you already had, and skips the mesh revision when a step produces the same geometry.
- Inverse kinematics and morph targets got the same treatment across 104 findings. A FABRIK chain validates its inputs before every solve, a look-at goal converts from world into parent-local rotation — so a bone under a rotated parent aims where you aimed it instead of somewhere offset — and pose buffers are allocated before a skeleton is retained. Morph targets keep implicit zero channels sparse rather than materializing them, accumulate CPU morph lanes in double with saturating fallbacks, treat an edit that changes nothing as a true no-op, and commit weight history only once the frame's CPU or GPU path has actually secured its resources, so a rejected draw can't overwrite the last accepted frame.
- Navigation bakes and agents are strict about their data. A navmesh bake validates its source geometry against the real mesh, rejects non-finite or fully degenerate input, and transforms normals through a cofactor inverse-transpose so mirrored and non-uniformly scaled meshes bake correctly. Area names keep their exact bytes through interning, import, and export; every serialized record is validated on load; and the wire format encodes zero-initialized structs, so a `.vnavmsh` written on one machine is byte-identical to the same bake on another. An agent answers its remaining path distance in constant time rather than walking every corner, a failed automatic repath leaves the path the agent already had instead of stranding it, and rebinding an agent rebuilds its active path instead of following a stale one.

### First- and third-person game runtimes

- The first-person work turns the renderer into an FPS-capable stack: view-model rendering, point-light shadows, height fog, auto-exposure and color-grading post-effects, raw and relative mouse input, and Doppler-shifted spatial audio with occlusion and ducking.
- The third-person suite adds what a character-action game needs: a spring-arm camera with target lock, character movement over moving platforms, combat volumes with health and ragdoll, cloth, cinematics with dialogue, AI perception and behavior trees, minimaps, quests, world persistence, and a baked-GI, reflection-probe, and procedural-sky lighting pass. Each subsystem behaves the same interpreted and compiled.
- A hand-written game loop stops applying its time scale twice. The documented pairing of `Update` with `StepSimulation(DeltaTime)` ran the frame's timing work in both calls — the time scale applied on top of itself, hit-stop decayed twice, frame and elapsed counters advanced twice — so a slow-motion or hit-stop effect came out as the square of what you asked for. The runtime recognizes that combined loop now and treats the delta you hand it as already scaled; a paused, hit-stopped, zero, or non-finite frame is a plain re-render; and a standalone `StepSimulation` keeps its historical unscaled behavior.
- A saved world is written the way the rest of the stack writes files. Game3D persistence and streaming storage validate their records before every read or growth, stage a complete replacement before publishing it, load a large save in n log n rather than quadratic time, reject duplicate or noncanonical keys, carry float bit patterns across machines unchanged, and refuse anything past the shared 64 MiB ceiling — so an interrupted or corrupt save is caught rather than half-loaded. Cloth, combat, audio, timeline, camera-fade, model-cache, navmesh, skeleton, and terrain data all grow through checked arithmetic now, and precise scene queries return a bounded, deterministically ordered result.
- A raycast-suspension `Vehicle3D` with an engine, brake, and steering model joins the stack, and `Game.UI` widgets now draw against either a 2D `Canvas` or a `Canvas3D`.
- The gameplay systems closed a 63-finding audit of their own, covering perception and behavior trees, interaction, footsteps, dialogue and facial animation, target locking, minimaps, and the stock effects. The through-line is entity lifetime: perception tracks and behavior-tree targets are weak references paired with stable entity ids, so a destroyed enemy can't be tracked through a slot that something else has taken over, and a health-dead entity is untargetable everywhere — collection, acquisition, cycling, and maintenance all release the lock with the proper lost transition instead of chasing a corpse.
- Sight and footstep rays exclude the character casting them, so an NPC no longer blinds itself on its own collider or reads its own capsule as the ground. Both now use the raw closest-body query rather than allocating a vector and a hit record per candidate, so a crowd of perceiving AI costs less per frame.
- Game3D's own core closed a 186-finding audit: handles, diagnostics, input, the entity hierarchy, the camera controllers, and the light presets. Every handle now requires a complete implementation layout before anything reads its private fields, and a call on an invalid or destroyed receiver stops at the trap even when your trap handler returns — so a stale reference can't read process-wide state or apply a side effect on its way out. Physics, animation, navigation, streaming, renderer, and spatial-audio diagnostics are atomic and saturating, so counters read from another thread stay truthful instead of tearing or wrapping.
- A frame with no time in it is a pause, not a corruption. Every controller — character, first-person, free-fly, orbit, follow, third-person, target-lock, and rail camera — treats a zero, negative, NaN, or infinite delta as a paused update that preserves input, movement, damping, lock transitions, line-of-sight timers, rail progress, boom, aim, and fade state exactly as they were. Controller, target, path, world, and camera bindings are validated as a whole before they're accepted, a cross-world assignment is refused with the previous valid binding still in place, and stale orbit and follow targets are released rather than tracked.
- Entities and presets change all at once or not at all. Reparenting, spawned-tree handoff, retained-slot replacement, body attachment, and entity construction roll back completely on failure — scene parents, entity parents, indexes, and retains together — and a corrupt parent cycle or runaway ancestry chain is detected rather than walked. The studio, outdoor, night, and interior light rigs are built complete before they replace the live one, so a preset that can't be allocated leaves you with the preset you had.
- Gamepad input is repaired before it reaches your game. Look sensitivity, snapshot flags, mouse deltas, wheel state, pad bindings, connection flags, and stick axes are checked against their documented bounds on every read; a pad that disconnects or is rebound has its stale snapshot cleared instead of continuing to steer; radial stick length is overflow-safe; and character movement reads the merged keyboard-and-bound-pad axis rather than one or the other.
- Bad gameplay data fails where you can see it. A behavior tree rejects cycles, duplicate edges, leaf parents, and multi-child inverters when you build it instead of misbehaving at evaluation. An empty conversation stays inactive, a choice-only one arms immediately, and NaN, infinite, or absurd reveal speeds, timers, and hold values are sanitized before they can wedge a conversation mid-line. Voiced clips and minimap images are type-checked before they are retained, marker ids are collision-checked, and interaction and footstep counters saturate rather than wrapping.
- The scripted-behavior classes closed a 185-finding integrity audit of their own. `Behavior3D`'s `FollowPath` consumes physical arc-length distance, so the speed you set is genuinely world units per second along the route rather than per path segment — a patrol crosses a curved route at an even pace instead of racing the straights. Spin axes normalize safely at extreme magnitudes, retained movement state and direct-update deltas are bounded, and phase arithmetic stays finite, so a behavior driven by a bad time step or an absurd parameter degrades instead of scrambling. `Character3D` repairs its own candidate-list bookkeeping, clamps its capsule and movement math, and produces a deterministic rejected delta even when you pass the same vector in and out. `Trigger3D` holds occupants through zeroing weak handles and grows its occupancy arrays transactionally, so a destroyed entity leaves the volume instead of lingering as a stale pointer, and enter/exit counters saturate rather than wrap.
- Scripted NPCs cost less per frame. Behavior ticks apply transforms directly instead of boxing a `Vec3` and a `Quat` every update, and a nav-assisted chase caches its target rather than repathing on frames where nothing moved — so the same crowd of patrolling, chasing, and triggering entities runs with fewer allocations than it did.
- The world and its cutscenes closed a 105-finding audit. A scene graph that shares nodes or loops back on itself is deduplicated before any of it is registered, every stable entity ID in a batch is validated before a single one is published, and a spawn that fails partway releases the IDs and registrations it had already taken instead of leaving them claimed. `Timeline3D` validates each track's kind, times, easing, retained payload type, and text before it plays or edits, and rebuilds its duration, marker, subtitle, overlay, and camera bookkeeping from the tracks that are actually there — so a cutscene assembled from partly bad data plays the parts that are good rather than following something stale.
- Movement probes and trigger volumes hold their shape under bad numbers. A 102-finding pass made the ledge, vault, clearance, and raw-overlap queries reject non-finite and over-ceiling input, normalize the pose they test from, and fill their outputs before returning, so a bad value produces no hit rather than an arbitrary one. A character clears stale ground support when it teleports or changes worlds and sweeps bounded platform displacement through collision instead of being carried through geometry; a trigger deduplicates its occupants and caps its fallback scans, so a volume can't double-count what's standing in it. The scene's spatial index validates its tree topology, leaf ranges, and cached bounds and rebuilds deterministically instead of walking a damaged node, and the ordinary full-collection query dropped a sort it never needed.
- Spatial audio behaves at the edges of a large world. A 100-finding pass normalizes a listener basis at extreme coordinates instead of letting it collapse, clamps Doppler input so a fast pass-by can't produce an absurd pitch, keeps an authored pitch and occlusion on a sound that has just started, and makes a distance override stick. Finished positional sources are pruned, a master-volume change reaches the sounds already playing rather than only the next one, turning occlusion off clears what it was already applying, and an ambient loop that failed or ended is retried instead of leaving a zone silent. The math underneath stopped allocating — listener and source updates run through stack-only direction transforms and allocation-free camera queries — so a scene full of positional sound costs less per frame than it did.

### Physics and runtime correctness

- The combat slowdown is gone. The spatial-query broadphase no longer rebuilds its cache on every pose change, so a fight that used to degrade over about fifteen seconds holds steady. `World3D.QueryBroadphaseRebuildCount` lets you watch the rebuild rate.
- 3D physics got a stability pass: joints solve against a true inertia tensor, resting boxes settle flat instead of micro-rocking, and a friction cone plus swept CCD keep fast objects from tunneling through walls.
- Ragdolls follow their skeleton. Every stage of ragdoll construction and playback — bind-pose segment lengths, capsule centers, joint anchors and frames, activation poses, velocity handoff, root motion, and the pose it publishes back — read bone translations from the wrong row of the transform matrix, so an ordinary chain collapsed to terminal defaults and joints anchored away from the bodies they held. All of it reads the canonical translation column now. Alongside that: a branched skeleton picks its farthest direct child for segment length, the total mass you ask for is distributed proportionally instead of through an additive floor, an activation that fails partway unregisters the bodies and joints it had already added, and a rig handed an animation controller or skeleton it wasn't built against is refused rather than driven from foreign data.
- Vehicles work on moving surfaces. Suspension damping and tire slip are computed relative to the body under each wheel instead of against world space, and the suspension and tire forces are applied equal and opposite to that body — so a car on a moving platform, a raft, or a physics-driven bridge behaves like a vehicle on a moving surface rather than sliding across it. Wheels whose ray missed drop out of the load denominator, each friction-ellipse axis normalizes against its own grip budget, and a chassis that isn't a dynamic body registered in the world you passed in is refused up front instead of stepping against nothing.
- The 2D graphics and physics runtime got the same treatment the 3D layer already had: strict action names and transactional input persistence, finite camera and parallax math, bounded pixel allocation, exact image-codec validation, alpha-correct transforms and rasterization, and sprite, atlas, batch, tilemap, and scene-graph paths that publish a whole result or none of it. Physics2D holds together at tiny and huge values — saturated integration, robust roots, checked ownership, and exact tile-crossing behavior — and cached transforms replace the per-frame rebuild.
- Several documentation-review findings landed as behavior fixes. VM callbacks run through the interpreter (`Lazy`, the `Option`/`Result` combinators, `Parallel`, and `Async` all work on both VMs), the regex engine lost its 32-group cap, locale parsing follows RFC 5646, collection membership uses value equality, and the time and calendar functions no longer depend on the host time zone.
- ChaCha20-Poly1305 clamps its Poly1305 key per RFC 8439 — some keys used to produce tags other implementations rejected — and every `Zanna.Crypto` entry point validates its handles before use.

### Runtime reliability audits

- An audit shored up the runtime's foundations. In practice: garbage collection, weak references, and shutdown finalization run deterministically; `Map` and `IntMap` growth is all-or-nothing; and long-running multi-threaded programs no longer risk the rare crash in monitors, channels, promises, or thread-pool teardown.
- Networking objects — HTTP clients and servers, TLS, WebSocket, SSE, SMTP — got stable identities and clean lifecycles, with strict protocol framing and predictable cancel, close, redirect, and keep-alive behavior.
- ZIP handling bounds metadata, expansion ratios, and extraction resources, so a hostile archive can't exhaust memory or disk, and a failed write cleans up after itself.
- ZPAK v2 adds a per-entry CRC-32 and compatibility flags to `.zpak` archives. Corruption is caught at load, and v1 archives still read.
- A second, deeper audit went back through the core. 160 findings across memory, GC, pools, traps, strings, threads and schedulers, every collection type, files, `SaveData`, watchers, archives, compression, networking, audio, and localization were recorded with their evidence, and 71 are fixed here. The themes: a handle that isn't live is rejected rather than dereferenced, an operation stops after a trap hook returns instead of falling through into a null read, growth and load-factor arithmetic is checked against a hard maximum count, and slots, keys, values, snapshots, and clones are staged off to the side and published once so a failure never leaves half an entry behind. The remaining findings stay open in the backlog with a recommended order, so nothing reads as finished that isn't.
- Asking the thread pool whether it's idle gets an honest answer. `WaitFor(0)` used to report outstanding work when all it had really hit was an idle worker holding the pool's monitor. Queued-plus-active work is published through an atomic counter updated on submit, completion, detachment, and finalization, so a zero-timeout poll answers the question you asked; task-error counts became atomic alongside it.
- Compression and file reads are all-or-nothing. The zstd decoder validates counts, weights, and every capacity step before it copies, and a `BinaryFile` read or write either completes or reports the failure — so a truncated or malformed stream gives you a named error instead of partial data.
- One deadline covers a whole HTTP request. The timeout you set is turned into a single monotonic deadline at the call and carried through name resolution, every address the client tries, connection reuse and stale-connection retry, the TLS handshake and each record read and write, HTTP/1 and HTTP/2 transport, every redirect hop, and the bounded transformations applied to the response. Each blocking stage gets only the time that remains. Expiry reports `Err_Timeout`, a timeout of zero is still explicitly unbounded, and per-request deadline state is cleared before a connection goes back in the pool, so one slow request can't shorten the next one. Governed by ADR 0228.
- Gzip decoding is bounded as it goes. A compressed response is checked against an absolute output ceiling and an expansion ratio while it decodes — 256 MiB, 128:1, and 1 MiB of slack for buffered HTTP bodies — so an over-expanding or hostile body is refused partway rather than after the whole thing is in memory. Every RFC 1952 member is validated, including optional headers, CRC-32, length, and exact DEFLATE boundaries. `Gunzip` and `GunzipStr` route through the same worker and skip three whole copies of your data on the normal path. Governed by ADR 0229.

### Codegen, IL, and the native linker

- Dense `switch` statements compile to a bounds check plus a jump table, and 16- and 32-bit overflow-checked math uses the CPU's flag bits instead of widening everything to 64 bits.
- A whole-function range analysis works out when a checked add, subtract, multiply, or divide can't trap and rewrites it to the plain form, so a safety check you don't need costs nothing. Loop strength reduction gets the same care: it swaps a loop's repeated multiply for an add only when it can prove every address stays in range.
- The interpreter stopped paying for your globals. A raw store used to scan every global to find the one it was writing, so an interpreted program got slower the more globals it declared. It computes the range directly now, which is what keeps a VM-profile game and a mission-scale scene responsive without compiling first.
- A register-allocation bug in the x86-64 backend is fixed. The pass that folds away redundant register moves could discard a register still live in a successor block, which showed up as the packaged Zanna Studio exiting during startup. Block exits are now treated as carrying their registers unless the code proves otherwise, and a regression test pins it.
- The IL specification moved to 0.3.0, covering the new jump tables, the branchless `select`, and the checked and narrow arithmetic.
- An IL-layer audit hardened the text and analysis pipeline: the parser enforces configurable resource limits and rejects malformed input cleanly, float constant folding follows IEEE-754 exactly, and the optimizer's analyses use bounded worklists instead of recursion, so very large functions compile.
- The native linker resolves cleanly on Linux and Windows/MSVC, finishes the CRT-less PE path on x86-64 and AArch64, and rejects dynamic imports that only exist on another OS, so a cross-platform mistake shows up at link time rather than on first run.

### Scene editing in Zanna Studio

Studio gained 2D and 3D scene editors this release, and then grew them from a first pass into something you can build a real level in. Opening a `.scene2d` file mounts the 2D editor; a `.scene3d` file mounts the 3D one. Each document keeps its own selection, view, and undo history.

One rule runs underneath all of it, so the rest of this section doesn't repeat it: everything Studio draws for your benefit — previews, overlays, editor lighting, project scenery, guides, and your view and layout state — is presentation only. It never enters your scene's bytes, its revision, its dirty state, or its undo history, and Studio never runs your game to produce it.

#### Scene files, objects, and schemas

- Scene files finally say what they are. `.scene2d` and `.scene3d` replace `.scene`/`.level` and `.vscn` as the names you'll see in new projects, and the extension tells you the format and the dimension without opening the file. The old extensions are permanent aliases, not a deprecation: everything that read them still reads them, in Studio, the runtime loader, streaming, and the `zanna asset` tools.
- Objects nest. Both editors show an expandable hierarchy instead of a flat list: create a child in one step, drag a subtree before, into, or after another node, and reorder siblings without the list shuffling under you. Duplicate and paste bring the whole subtree, and Find locates an object by ID or type without disturbing your selection. A parent can't be dropped into its own descendant.
- A hierarchy holds a real level's worth of objects. The 3D tree asks for the rows actually on screen instead of keeping a widget per node, which raises the ceiling from 4,096 nodes to 65,536 with every part of the tree intact — multi-select, before/into/after drops, inline rename, type icons, dimmed pick locks, and reveal-on-select. Opening a 2,000-node scene took about 45 seconds before; it takes about 1.3 seconds now, interpreted.
- Scenes and objects carry typed data. Scene-wide properties and per-object metadata hold a Boolean, integer, float, string, or an explicit null, and keep that exact kind through a save and reload — so gameplay data like a role, a trigger, or a spawn count lives in a field instead of being smuggled into a name. Scene files advance to VSCN v6 to store it; scenes you saved with an older Studio still open.
- Properties are rows you edit in place. Scene metadata, per-object properties, and 3D gameplay metadata are now a list of `key / kind / value / ×` rows that are always editable, with a blank row at the bottom for the next one, instead of a list plus a separate key-type-value form behind Set and Remove buttons. Changing a value, renaming a key, or switching a kind each commits on its own; with several objects selected, one shared row sets or clears a key across all of them.
- Component schemas keep objects consistent. A `scene-components.json` at your project root describes the property sets an object should have. Studio flags objects missing a set and applies it across a whole selection in one action, and schema editing is conflict-safe with its own undo history.
- Component schemas gained enum and asset fields. An enum field renders as a dropdown over a fixed choice list; an asset field holds a workspace-relative path and filters the asset browser to images, audio, or scenes. Both stay ordinary string values in the scene, so game code reads them with the getters it already uses. Studio writes the lowest schema version your content actually needs, and upgrading existing files goes through a scan/review/confirm pass that reports per-file refusals instead of rewriting silently.
- Gameplay data authors as a form, not a wall of rows. A schema can declare color swatches, bounded sliders, angle and vector fields, name-labeled enums, and repeating groups, so a mission's sky rig and objective list arrive as labeled, grouped controls rather than dozens of raw metadata lines — and an enum's stored value is annotated with its declared label wherever the raw grid still shows through.
- A component can also say how to create the thing it describes. Give it a creation recipe — the 2D object type or the 3D node name it produces — and Create Object and Create Node build a gameplay-ready enemy, pickup, or spawn with that identity and the component's declared defaults already set, in one transaction with its own selection and preview refresh. That replaces the old routine of dropping a generic placeholder, typing its runtime identity by hand, and running Add Missing afterwards — a sequence that left a real history entry holding an object your game would have rejected. A project without recipes behaves exactly as before.

#### The 2D canvas

- Selecting and moving things feels direct. In 2D, click with a modifier to add or remove from the selection, or drag a marquee over the canvas and everything it touches highlights as you go — Escape cancels without touching the scene or your undo stack. Dragging a group keeps the objects' relative positions, and arrow-key nudging works in pixels or tiles.
- The 2D tile tools cover real map work. Paint and Erase capture gap-free strokes with Escape rollback, Rectangle previews and applies an inclusive area once, Fill replaces one four-connected region, and Pick samples the active layer straight back into Paint. Line and Ellipse join them, each previewing the exact cells it will write as you drag and committing them in one step when you let go. Holding Alt in any of the paint-family tools turns the next click into an eyedropper, so you can sample a tile mid-stroke without leaving the tool you're in. Every completed change is one undo step, while previews, picks, cancellations, and no-ops stay out of history.
- A preview shows the tiles, not an outline. Paint, Fill, stamps, and the shape tools composite the actual atlas frames they're about to write, ghosted over the map, so the preview and the result are the same picture. Switching tools repaints immediately and drops an active stamp, and each document keeps its own tool choice.
- Autotile resolves while you work, on by default. The canvas applies your autotile rules with the same neighbor masks and rule precedence `Tilemap.ApplyAutoTile` uses at runtime, so a wall or a path you paint reads as the finished thing rather than a field of base tiles — and the cells on disk keep their authored base IDs, so nothing about the preview changes what you save. Hovering a single-cell Paint or Erase previews both the variant that cell would become and the neighbors it would change. Animation preview composes on top of it.
- Tiles move in blocks. Box-select on the canvas now leaves a marked region on the active layer, and the canvas menu can copy, cut, delete, or paste it — paste clips at the scene edges rather than refusing, and each operation is a single undo step. The same region becomes a multi-tile stamp: pick "Paint with Region Stamp" and the Paint tool writes the whole block per stroke, grid-aligned so a drag tiles it seamlessly, with a ghost frame showing what the next click will lay down. Escape or any tool switch returns you to single-tile painting. Blocks travel through a tagged clipboard format, so pasting ordinary text into a scene does nothing rather than something strange.
- The tile palette handles a big atlas. Zoom runs 50% to 300% without touching your artwork, pointer hits stay exact at every zoom, and typing a tile number reveals and selects that frame instead of making you hunt for it.
- The canvas has rulers and guides. Cell-coordinate rulers track the canvas's scroll, zoom, and centering exactly. Clicking the top ruler toggles a vertical guide and the left ruler a horizontal one, a captured drag creates or repositions either with a live preview, Escape restores what was there, and dragging a guide off its ruler removes it. Rulers hide to reclaim the space, and up to 64 guides per axis follow the owning tab.
- The Layers panel became a navigator. Each row shows its layer's visibility, lock, solo, and non-default opacity at a glance; Enter or a double-click toggles authored visibility as one exact history entry. Rows drag to reorder with an insertion marker and edge auto-scroll — Alt+Up/Down does the same from the keyboard — and the Add, Remove, Up, and Down buttons share that one canonical transaction, disabling truthfully at the first and last layer. Lock and solo remap to the same live layer across every one of those moves and prune when their layer goes away.
- A layer can be translucent, and it's authored data. Each 2D layer carries an optional opacity — edited from a spinner in the Layers panel, one undo step per change — and the canvas composites it truthfully, so a dim background or a ghosted overlay layer looks in the editor exactly as it will in the game. The field is written only when it differs from fully opaque, so existing scenes round-trip byte-identically, and your game reads it through `SceneDocument.LayerOpacity`. Alongside it, Lock refuses every tile writer on a layer with a visible reason and Solo previews one layer by itself — both workspace-only, neither authored.
- 2D objects carry a real transform. Rotation about a pivot, per-axis scale, horizontal and vertical mirroring, and an RGBA tint are now first-class fields on a scene object, so a flipped crate or a rotated sign is authored data instead of something your gameplay code has to reconstruct from a naming convention. The canvas draws an object's sprite at its native size with the whole transform applied, selection outlines follow the transformed shape, and clicking tests the rotated sprite rectangle rather than the origin cell — so what you click is what you see. A single selected sprite gets on-canvas handles: corner squares scale it about its pivot in its own rotated frame, and a handle above the top edge swings it around. Each drag is one undo step and Escape backs out of the gesture without changing your selection. The inspector edits the same values numerically, with the tint as `RRGGBBAA` hex. Your game reads and writes the same fields through `SceneDocument.ObjectRotation`, `ObjectScaleX`, `ObjectFlipX`, `ObjectTint`, `ObjectPivotX`, and their setters — the engine stores and hands them over without interpreting them, so your sprite pipeline stays yours.
- Your existing scenes are untouched by any of that. A transform field is written only when it differs from its default, so a scene that never rotates or tints anything saves exactly the bytes it saved before — no migration, no version bump, no re-export.
- How a tile behaves is part of the scene. Collision, per-tile gameplay properties, frame-by-frame animations, and 16-variant autotile rules are typed scene data with an editor behind them, and `SceneDocument.BuildTilemap` applies them on load — so a game can drop its hand-written tile registry entirely. The tile palette badges which tiles carry collision, properties, or animation, so you can see a map's rules without opening a file.
- 2D gameplay data has real editors, not raw rows. An object can carry a bounded collider — box, circle, or tile rect, with half extents, radius, offset, and a trigger flag — with its own inspector that commits per completed gesture, and the canvas draws collider wireframes with trigger volumes distinguished from blocking ones. Sprite clips work the same way: start frame, frame count, per-frame delay, and loop, each create, edit, and remove a single undoable transaction with normalized writes. Both are ordinary typed properties your schema can publish as creation recipes, so your game reads them with the getters it already uses.
- Scene camera and lighting are authored too. Follow or fixed mode, world bounds, deadzone, follow smoothing, zoom, darkness, tint, and the player light all live in the scene, with bounds and deadzone drawn as canvas overlays. Every field is optional and range-checked, and each maps one-to-one onto the camera and lighting call your game would have written by hand.
- You can watch the scene move before you run it. A Preview toggle plays authored tile animations on the canvas using the same per-frame durations the runtime uses, and can dim the canvas to the authored darkness. It repaints only the cells that changed, pauses when the tab isn't active, and leaves every tool working while it runs.
- Big 2D maps stay workable. The canvas rasterizes only the tiles currently in view, so a very large map scrolls smoothly and edits correctly all the way to its far corner instead of allocating the whole thing. Zoom picked up a true 100% (one scene pixel to one screen pixel), fit-to-window, zoom anchored under the cursor, and a grid toggle that stays where you put it.

#### The 3D viewport

- The 3D viewport shows the real scene. It renders the live scene graph through the offscreen `Canvas3D` path described above — shaded or as triangle wireframe, with overlays that stay aligned to it — so on macOS the viewport is GPU-accelerated and on Windows and Linux it falls back to the software rasterizer, with Studio saying which one you got rather than pretending. The viewport also sizes to its pane instead of stopping at a fixed cap, and interactive camera and gizmo drags render at reduced resolution and snap back to full resolution the moment you let go, with no per-frame allocation in the path that gets the rendered frame onto the pane.
- Navigating the 3D viewport is flying, not scrolling. It defaults to perspective — switchable back to orthographic — with fly, orbit, pan, and frame-selection controls, so judging depth, sightlines, and the feel of a space is something you do by moving through it. Overlays and picking share the one camera, so what you click is what you see in either projection. Overlay visibility and culling statistics are configurable, and each scene remembers its view.
- Getting around a scene you know is fast now. An orientation navigator sits in the viewport's top-right corner: six axis-aligned faces you click to turn the camera, active and hover feedback, a compact XYZ cue, and a Perspective/Orthographic chip. It owns its own pointer input, so a click on the widget turns the camera instead of leaking through as an orbit or a selection, and the Top, Front, and Right toolbar buttons remain as keyboard-reachable equivalents. Shift+1 through 9 bookmark the complete camera pose — angles, zoom, target, projection — with a bare digit recalling it, remembered per document. The viewport mode button cycles Shaded, Wireframe, and a combined Shaded+Wire that draws the wire pass over the shaded frame, and the stats readout breaks the frame into per-pass CPU milliseconds. The selected material-library entry renders as a live lit-sphere swatch.
- Zooming the 3D viewport is continuous. The wheel and the zoom buttons scale smoothly between 0.05 and 400 pixels per world unit instead of stepping through fixed levels, so you can frame a doorway as readily as a whole mission. The grid changes decade on its own to stay legible and holds still in world space while you pan, and your zoom comes back to the hundredth after a restart. The inspector's rotation fields decompose through the runtime's own `Quat.ToEuler` now, so what the inspector shows can't drift from the convention it writes.
- Clicking picks what the pixel shows. The viewport tests the triangles under your cursor rather than object bounding boxes, so clicking through the visible gap of a torus, an archway, or any concave silhouette selects the mesh you were aiming at instead of the near object whose empty box corner the ray crossed. Objects with no mesh keep their bounded origin markers as a fallback. Alt-click cycles front to back through whatever is stacked under the pointer, so a prop buried inside a room is two clicks away rather than unreachable.
- Rubber-band selection came to 3D. Drag from empty viewport space and everything whose on-screen bounds the rectangle touches is selected, with the same modifiers the 2D canvas uses — replace by default, Shift adds, Ctrl/Cmd toggles — and Escape abandons the drag without touching your selection. Selected and hovered meshes draw corner brackets so you can tell at a glance what a click is about to take.
- Set dressing gets out of the way of your clicks. The 3D hierarchy carries a common-action strip above the tree: Show and Hide resolve a whole mixed selection through one history transaction, and Lock Pick keeps a node rendered while it yields viewport clicks to the geometry behind it and steps out of the marquee's way — hierarchy selection and inspector edits still work, so it's how you reach the wall inside a room full of props. Locked rows carry a visible cue and the button flips to Unlock Pick when everything selected is locked. Locks live with the open tab, follow their node through reorders and reparents by identity rather than by row, and vanish with a deleted node instead of transferring to whatever inherits its place.
- Creating something puts it where you're looking. In the 3D viewport, a right-click create lands on the triangle under the pointer, on the ground plane when the ray misses geometry, and at the view target when it misses both; the toolbar's primitive buttons spawn at the view target instead of the world origin, and Cylinder joins Box, Sphere, and Plane. In 2D, "Add Object Here" creates one selected object at the cell you right-clicked. Either way the new object's name is armed for editing, so you can name it by typing. Holding Ctrl/Cmd while dragging an object suspends grid snapping when you need a placement between cells.
- Placement is exact rather than eyeballed. Drop to Surface sets the selection down on whatever is below it; surface-constrained dragging slides an object across the geometry under the cursor and can align it to the surface normal, so a crate sits flat on a ramp instead of floating through it; and vertex snapping pulls the object — or its pivot — to a real mesh vertex read from the geometry itself, falling back to a precise surface hit when no vertex is close enough. Each of them excludes the object you are moving from its own hit test, participates with the project scenery drawn around the scene, commits one history entry when you release, and restores the original transform exactly on Escape or on any failure.
- Move, Rotate, and Scale are per-scene tools with Local and World modes and snapping. Rotation rings project correctly and don't flip when you drag past the wrap point, plane handles appear when the view makes them usable, and a group transform converts parents before children. Escape or a failure rolls the whole gesture back — you never get a half-applied move.
- Layout commands round out group editing. Arrange… aligns a same-parent selection to the primary node or distributes it evenly along any axis in one undo step, arrow keys nudge the selection along world axes (Shift for big steps, PageUp/Down for height), and a Pivot toggle chooses whether a group rotate or scale spins each node in place, orbits everything around the primary node, or turns about the selection's center. Import got settings — a uniform scale factor and a Z-up conversion applied as the asset lands — and when a scene carries baked animation clips, an Animation panel lists them and previews rigid-node clips on the selected subtree without ever touching the document; Stop puts every transform back byte-exactly. A Navmesh view option overlays the baked walkable surface so you can see what agents will actually traverse.
- Reparenting preserves what you see. Moving an object to a new parent keeps its world position exactly, or you can opt out and keep its local transform. A transform that can't be represented exactly — singular, sheared, or lossy — is rejected outright rather than silently rounded.
- Terrain is authored in the scene, not beside it. Create a heightfield node — a square grid of 9 to 65 samples a side — and Raise, Lower, Smooth, and Flatten viewport brushes sculpt it under the cursor with live feedback, one undo step per gesture, and cancel support mid-drag; a focused terrain inspector holds its settings. The surface is an ordinary VSCN mesh node carrying typed `terrain.*` metadata, so what you sculpt is byte-for-byte what your game loads, with no sidecar heightmap and no editor-only stand-in that can drift from the shipped geometry.
- The 3D status line stopped trying to be a diagnostics panel. It now keeps nodes, lights, the active project state, active/direct/filtered preview counts, render mode, and transform tool readable at a glance; the complete camera pose, pixel scale, materials, fallback, missing-resource, clipping, and timing detail remains in its wrapped tooltip and accessibility description.

#### Lights, materials, cameras, and baking

- Editing a transform is live. Typing in a position or rotation field moves the node as you go and writes the scene once when you leave the field, as a single undo step; Escape puts back what was there. A built-in component picker adds a Light, Material, Camera, or Collider with sensible defaults, and a multi-node selection reports a truthful mixed state instead of showing you whichever node happened to be first.
- Material editing works across a selection. Mixed values show as mixed instead of showing whichever object happened to be first, editing writes only the fields you actually changed, a shared material is copied before it's edited so you don't disturb other objects using it, and embedded texture maps can be assigned or cleared for a whole batch. Visibility handles mixed selections the same honest way.
- Lights are editable scene content instead of import-only data. Add a light node or inspect any existing directional, point, ambient, spot, rectangle-area, sphere-area, or volume light, including its local offset/direction, falloff, range, emitter shape, shadows, and spot cone. Hierarchy badges and viewport color, direction, offset, and range markers keep meshless emitters visible and pickable. Lights edit in batches the same honest way materials do: select every practical in a mission and the shared fields edit together while genuinely mixed ones read as mixed, with the whole change staged across the selection before any of it is applied — so a light pass over dozens of nodes is one undo step rather than dozens of visits.
- Cameras are scene content you can author. Add Camera drops a real `Camera3D` node you can position and tune, with a frustum marker in the viewport, a look-through mode that puts you behind the lens, and a small picture-in-picture preview so you can watch what a camera sees while you work somewhere else in the scene.
- Colliders and gameplay markers are visible and editable. A placed mesh can carry a typed collider — box, sphere, capsule, or its own mesh — and the gameplay data around it (patrol routes, cover points, spawn markers) draws in the viewport as badges, routes, and shapes instead of anonymous origin dots. It's typed node metadata plus your project's component schema, so no format change and your game reads it with the getters it already has.
- A project can have one material palette. Drop a `materials.scene3d` at a workspace root and its named materials become a library the whole game shares; picking one clones it into the scene, so a game's canonical metal, rock, and foliage surfaces are chosen from a list instead of rebuilt per scene. Editing the library is conflict-guarded with its own undo history.
- A scene can be placed inside another scene. A prefab reference stores "this subtree comes from that file" instead of a copy, so forty placed lampposts are one source you can fix once, and per-placement overrides survive the update. Recursion is bounded by cycle, depth, and fan-out guards, a missing source leaves a visible placeholder rather than losing your placement, and reload, unpack, and relink are single actions when a placement should become ordinary content. Scenes that use prefabs save as VSCN v7, the current version; anything you saved earlier still opens.
- Importing into a scene you're working on keeps what you imported. An imported scene's animation clips are adopted before its nodes are grafted in, so saving afterwards no longer drops the rig you just brought in, and merging into a scene that already has content leaves your camera where you left it instead of reframing. The import dialog accepts `.scene3d` files alongside the model formats, and embedded Play forwards pointer movement in whole game pixels so sub-pixel jitter can't re-fire a move.
- Baked lighting and environment are authored in Studio. A bake panel runs the static lightmap bake, probe grid, skybox, and IBL assignment in resumable chunks with visible progress, writes the probe grid to a sidecar, and keeps the environment settings on the scene root — so the lighting quality that used to require hand-written baker calls is a panel you drive and watch.
- Bake Navmesh writes the walkable surface your game loads. The 3D bake inspector reads bounded `nav.*` settings from the scene root, voxel-bakes through `NavMesh3D`, and writes a `.vnavmsh` sidecar beside the scene. Agent radius, agent height, maximum slope, and cell size are typed Scene Settings, and your game imports the sidecar from the same scene path it already loads.
- An Editor light brightens the viewport when an authored night scene is too dark to work in. It raises the ambient level in the authoring viewport only, so what your camera previews show stays exactly as authored.

#### Seeing your game in the editor

- A project can teach Studio how its own scenes should look. Your `scene-components.json` grew optional preview profiles: rules that map an object's type to a sprite and frame in 2D, and a marker's metadata to a prefab `.scene3d` in 3D — with the frame or the model variant, the facing, and the scale chosen from the object's own typed properties. So a `spawn` marker draws as the enemy it spawns and a `prop` marker draws as the crate it becomes, and a mission full of anonymous origin dots becomes a level you can read at a glance. The rules are declarative data you check into source control.
- Objects show what they are. An object can point at a sprite image and frame and the canvas draws it in place of the generic marker — at its native size, with whatever transform the object carries — and objects that form a route draw as a connected polyline. It's a display convention in an `editor.*` namespace that games ignore, and previews share the existing image budgets.
- Sprites stack the way your game stacks them. Studio used to paint every object after every tile layer, in whatever order the scene file happened to list them — so two overlapping sprites could pick a different winner in the editor than in the game, and a foreground tile layer could never cover anything. A preview rule can now place each kind of object in the draw stack: before the tiles, after a named tile layer, or over the whole map, with a per-object metadata override for the deliberate exception. Rendering and picking share the one order, so the sprite you see on top is the one your click selects, and a bridge, canopy, or roof previews as the overdraw it is.
- A 2D scene can sit on your game's own background art. The same file takes a `scenePreview2D` profile: a fallback image, and optionally a scene property that picks one of up to 64 variants, so region 3 gets region 3's sky. Studio composites it after the canvas clear and before tiles, objects, guides, and overlays, scaled to cover, contain, or stretch as you choose. Paths are project-root-relative, so moving a scene inside its project doesn't break its art; a missing or out-of-range property falls back to the default image, and with no profile at all you keep the ordinary clear color.
- A 3D scene can open the way the game will show it. Point the same file at the float and Boolean metadata your scene root already carries and Studio will start the camera at the player's start pose and eye height, use your gameplay field of view, generate a sky from your zenith/horizon/ground palette (with clouds, stars, and a sun glow), light the scene from your key and fill directions, add sky IBL, and apply your distance and height fog. Missing or wrong-typed metadata falls back to ordinary editor lighting rather than failing, and an authored `env.skybox` always wins over the generated one. The initial camera and overlay defaults apply on a document's first open; after that your own view choices are what come back.
- A 3D scene can be surrounded by the terrain your game builds at runtime. Name an environment prefab — and optionally a set of variants chosen by a root property — and Studio loads that `.scene3d` beneath the disposable preview graph, sharing the same read, cache, and node budgets as everything else it draws for you — so an authored arena sits inside the canyon your game generates at runtime. An asset that's missing, invalid, or over budget reports preview status instead of changing your scene.
- Runtime-built scenery can layer instead of taking turns. A project may add up to 32 independently conditioned environment prefabs beside that base terrain: exact Boolean, integer, or string root metadata decides whether each layer is present, and optional float metadata drives its position, scale, and yaw. The layers share the gameplay camera, lighting, fog, and post-processing, but never enter the hierarchy or your selection.
- Water in Studio is now real runtime water. A project can declare up to eight bounded `Water3D` previews with metadata-driven center and dimensions, project textures and normal maps, 8–64 grid resolution, and up to eight wave records. Studio submits the editable scene, disposable project scenery, and transparent water in one frame so depth, sorting, fog, and post-processing agree. It's the game's own water image, normal map, dimensions, and waves; animation remains presentation-only and capped at 30 Hz.
- Runtime-selected materials can appear without changing the scene. An ordered rule maps exact typed node metadata to project albedo, normal, metallic-roughness, ambient-occlusion, and emissive maps plus bounded PBR, environment, SSR, and fixed or scene-colored emissive values. Studio clones the authored material for the shaded frame and restores the original reference immediately afterward.
- Stateful scenes can show one state at a time without hiding authored data. A project can expose a bounded selector over exact Boolean, integer, or string node metadata; All is always available, while nodes without the property remain visible. The choice follows the scene tab and session and rebuilds only disposable preview art, so a wave-based mission opens on the encounter players meet first instead of drawing every spawn in the level at once.
- The viewport can run your project's post-processing. A profile can carry a static chain — tone mapping and exposure, bloom, color grade, vignette, and FXAA — applied in a fixed portable order regardless of how you wrote it, so a scene is graded in Studio the way it will be graded in the game. Each group is all-or-nothing and range-checked, and a malformed one rejects the whole schema rather than half-applying. Effects that depend on depth, frame history, or a particular backend — SSAO, SSR, depth of field, temporal AA, motion blur — are deliberately left out until they can promise the same result on every platform.
- Game View takes the editor out of the picture. One toolbar action drops everything Studio paints for your benefit — grids, rulers, guides, fallback markers, light halos, route lines, camera bounds, selection outlines, gizmos, brackets, the camera inset, the orientation navigator — while keeping the project's own backgrounds, sprites, animated tiles, environment, lighting, and post-processing exactly as they are. It frames the picture your game will present rather than the one your docks happen to allow: a project can declare its output size, and Studio composes to that aspect inside the viewport, mattes the leftover space, and drives a 3D camera at the game's real aspect ratio — so resizing a pane no longer changes the composition you are reviewing, and a screenshot taken here is directly comparable to one from the running game. Leaving restores your camera, zoom, and scroll precisely.

#### Running your game

- Run Scene launches the game at the scene you have open. It uses the owning project's normal run configuration and appends the active scene's path, with the same streamed output and status as an ordinary Run. It's now Ctrl+R or an action in each editor's Scene menu, and a documented `--scene-watch` convention closes the loop: a game that honors it re-loads the scene whenever the file's timestamp changes, treats every reload as a fresh load, and keeps the previous scene through a torn write or a file that doesn't parse — so saving in Studio updates the running game.
- Play runs the game inside the editor. A project declares a `run-profile` of `vm` or `native`, and both editors carry an always-reachable Play button: a native project builds first if its sources changed, a VM project launches straight under the interpreter, and either way Studio injects a shared-memory channel and the game's frames arrive in the 3D viewport or on the 2D canvas while the editor's own rasterization yields. Mouse and gameplay keys forward while the pane has focus, the game's own window stays hidden on Windows, macOS, X11, and Wayland, and the pane says building, waiting, live, stopped, or exited rather than guessing. Nothing about it touches the scene you have open.
- Embedded Play attaches on macOS too. The channel's native shared-memory key is derived by hashing your portable channel name rather than embedding it, so a name up to the existing 96-byte limit fits within Darwin's far shorter shared-object limit and still resolves to one stable identity for both the editor and the game. Each Studio probe takes a clock-derived name as well, so a channel abandoned by a run that ended badly can't block the next Play.
- A project starts as a game rather than a blank folder. New Project adds "2D Game" and "3D Game" to the console, GUI, and library templates, and each one scaffolds atomically — a run-profile manifest, a starter scene, an asset library, a typed-forms schema, and a `main` that already handles `--scene`, `--scene-watch`, and `--smoke` — so Run Scene, hot reload, and Play work before you write a line, and a scaffold that fails or collides deletes its staging tree instead of leaving half a project behind. Package Project ships the finished thing: it runs `zanna package` for the open root as a streamed job you can watch.

#### Projects and assets

- Launching a scene by path opens the project that owns it. Studio walks up from the file to the nearest `zanna.project`, opens that root as the workspace, and records it in your recents, so the scene comes with its component schema, preview profiles, and material library rather than whatever session was open last. Unsaved buffers from the previous session are still restored; clean tabs and unrelated roots stay out of the way.
- A workspace asset library gives the browser something to work with. An `asset-library.json` at a root tags your notable assets and records their native tile grid, so picking the right atlas is a filter rather than a hunt. Entries whose file has gone missing are kept and badged rather than dropped, writes are atomic, an outside edit is detected, and the library has its own undo/redo separate from the scene.
- The asset browser shows the assets. It opens on a responsive card grid: PNG, JPEG, BMP, and GIF cards show the decoded picture, and `.scene3d`, `.vscn`, glTF, FBX, OBJ, and STL cards render the real mesh framed under neutral light through the same portable software-capable `Canvas3D` path the viewport uses, so you can find a model without opening it. Everything else keeps a clear vector file icon. Only cards actually on screen render, at most one per frame, with a bounded number kept — so a folder of heavy assets scrolls rather than stalls. The compact list is still one click away, tags badge cards and rows alike, and your selection and drag payloads carry across both views.
- Assets drag from the browser into the scene. Drop a project image on the 2D canvas and you get a sprite object at that cell, carrying a portable reference rather than a machine-specific path. Drop a 3D asset on the viewport and it imports through the normal path; drop a material-library entry on a mesh and it lands on that mesh. Each is one undoable transaction, and dropping the wrong kind of file is refused without disturbing your history.

#### Working in the editors

- Each editor is a three-pane workbench. A dedicated hierarchy pane on the left, the canvas or viewport in the middle, the inspector on the right, with split positions remembered per document and the side panes collapsing on their own when the window gets too narrow to use them. The 2D tile palette moved under the canvas where it belongs, and inspectors split into Object and Scene tabs that follow what you have selected while still respecting a tab you chose by hand. The Scene tab then uses one per-document Topic selector: 2D offers Setup & Import, Properties, Camera & Lighting, Layers, Tile Behavior, and History; 3D offers World, Lighting & Bake, Assets & Materials, and History. Only the chosen complete topic is laid out, so adding power no longer makes the inspector an endless wall.
- The panes hold up as you resize them. Rows wrap instead of running off the edge, panels clip to their own bounds so nothing paints over a neighbor, hiding a widget repaints the space it vacated instead of leaving a ghost, and controls stay reachable and correctly hit-tested at intermediate widths rather than only at the one the layout was designed for.
- The panes come off the frame. The hierarchy, the inspector, and the 2D tile palette each carry a Float button that moves the pane — state intact — into a floating panel, with the vacated split collapsing so the canvas gets the room; Dock puts it back exactly where it was.
- The toolbar stopped growing with the feature set. Each editor keeps its working tools on the bar — paint tools in 2D, Move/Rotate/Scale and Game View in 3D — and moves document, creation, placement, camera, overlay, and layout commands into stateful Scene, Tools, Create, Placement, and View menus that are present at every window width. Widening the window now gives the level more room instead of putting every primitive and camera button back on screen; narrowing it folds the 3D command bars into overflow menus rather than truncating them, so no command ever becomes unreachable.
- Both scene editors can take over the window. Scene Layout hides Studio's outer docks while keeping the scene panes; Focus also hides the scene chrome so the canvas gets everything. Either is one click, one View-menu item, or Shift+Space, and both restore the exact layout you had. A scene tab enters the authoring layout the first time it becomes active — but an explicit Exit Layout stays honored for as long as that scene is up. At an ordinary 1,440-pixel desktop width, the authoring layout now keeps a compact hierarchy and inspector docked around a canvas-first or viewport-first center instead of waiting for an ultrawide lane; saved divider choices still win, and narrower lanes retain the full-width master/detail flow. Narrow windows switch to compact chrome, the Hierarchy, Objects, and 2D palette panes have their own toggles that persist with the workspace, and a newly opened 2D scene frames on its authored content, preferring the player start, with Frame Selected alongside it.
- Every scene surface has a right-click menu. Both hierarchies offer create (including 3D primitives, lights, and cameras), rename, duplicate, delete, ordering, and framing; the 3D viewport offers creation and framing; the 2D canvas adds an object at the clicked cell, works on the tile region, and switches tools. The menus call exactly the same operations the toolbar and shortcuts do, so validation, undo history, and the dirty marker behave identically no matter how you got there. The 3D menu waits for the right button to come up in place, so it never interrupts a look-around drag.
- Small edits happen where you already are. `F2` on a single selection opens an editor right on the hierarchy row, pre-filled with the current name; Enter or clicking away commits one undo step, Escape abandons it, and a 2D rename onto an id that already exists is refused with the same message the inspector gives you. Numeric fields scrub: drag sideways on a spinner's value area to adjust it continuously — Shift for coarse, Ctrl/Alt for fine — and the whole gesture lands as one undo entry when you release, while a click without a drag still puts the caret in the field to type.
- The keyboard belongs to whatever you're pointing at. The canvas and viewport own their own shortcuts for selection, transform modes, framing, nudging, and Escape, so typing in a text or number field never triggers a scene action by accident. `F1` through `F12` are delivered on every platform now, which is what makes `F2` rename work everywhere.
- You can see and steer your editing history. Both editors carry a History panel on the Scene tab listing your undoable edits oldest-first with their labels, plus a Current row; clicking an older row jumps the scene there by running the equivalent undos, so redo stays available and the bytes match stepping back by hand. The list follows its own document across tab switches. During a transform drag, holding Ctrl inverts snapping in either direction, and a rotate drag shows the swept angle live to a tenth of a degree.
- Scene edits no longer stage through temporary files. The 3D editor serializes to memory for commits, undo, and redo instead of writing sibling files next to your scene, which makes edits faster and stops leaving stray files in your project. Undo history is bounded by total size as well as step count, so a session on a large scene doesn't grow without limit.
- A scene you're not touching costs nothing. An idle 2D or 3D tab used to keep damaging and repainting the whole workbench, viewport image included, every frame. The menu and toolbar chrome now caches its state between changes and the language-service frame stays out of the scene's way, so an open scene sits quiet until you do something to it.

### GUI toolkit

- A large rework sits behind the same public surface, so your GUI code keeps working while the toolkit under it gets better.
- Themes are scalable and per-app now, with custom palettes, contrast policies, and reduced-motion support.
- Text editing handles Unicode 17 graphemes correctly and supports IME composition on Linux, macOS, and Windows, so non-Latin input works everywhere. Glyph rendering keeps up: gamma-correct blending, OpenType ligatures, per-glyph font fallback, and TrueType-collection (`.ttc`) loading, so coding fonts and mixed-script text render cleanly at any size.
- A shared semantic tree feeds each platform's native accessibility layer, so screen readers see real widget semantics.
- Virtual list and tree models render only what's on screen, which keeps large data sets responsive. Interactive data grids and full flex/grid/dock layout round out the widgets.
- A built-in vector icon library lets toolbars, trees, tabs, and status bars ask for an icon by name and get crisp strokes at any scale, with no bitmaps to ship.
- The widgets picked up what tool-style apps need: multi-selection and row-aware drop targets in `TreeView`, scrolling a nested descendant into view, an indeterminate `Spinner` for a mixed-value field, and public `LeftSuper`/`RightSuper` key constants so Command and Windows keys are bindable.
- Direct manipulation is built in rather than reinvented per app. `TreeView` edits a row in place — Enter or clicking away commits, Escape cancels — `Spinner` scrubs its value on a horizontal drag and reports when the gesture finishes so you can fold it into one undo step, and a drop target can ask where the pointer was when the drop landed instead of guessing from the live cursor. An `Image` can opt into keyboard focus and draws the theme's focus ring, so a custom-painted surface behaves like a real control.
- `F1` through `F12` arrive from every backend — macOS, Windows, X11, and Wayland — so function-key shortcuts work the same everywhere instead of only where the platform happened to map them.
- A `ListBox` can be reordered by dragging. Turn it on and a real drag moves a row, with an insertion marker showing where it will land and auto-scroll near the edges; Alt+Up/Down does the same from the keyboard. The control never rearranges your data behind your back — it reports the one move the user asked for and your code validates, applies, and rebuilds, which is how Studio turns a layer drag into exactly one undo step. A click that doesn't cross the drag threshold, a drop back where it started, and Escape are all no-ops.
- A tree can hold tens of thousands of rows without giving anything up. `VirtualTree` asks your model for the rows that are actually visible instead of retaining a widget per row, and it keeps the whole tree contract while it does: vector or glyph row icons, selected and dimmed row styles, toggle and range multi-selection, subtree removal, before/into/after drop targets, reveal-a-row, point lookup, and inline rename that reports when it commits. It's public API, so your own tools get the ceiling Studio's scene hierarchy now runs at.
- Tooltips read properly. Wrapping breaks at the last whole word that fits instead of mid-word, an over-wide word splits on character boundaries rather than through a UTF-8 sequence, and your own newlines and blank lines come through as written. A tooltip whose text changes while you're hovering re-measures in place, and one that's cleared disappears, so a stateful control never leaves stale guidance on screen. Anchored and follow-cursor tooltips also wrap to a usable width and clamp themselves inside the window, so a long hint near an edge stays readable instead of running off the panel it belongs to.

### Languages

- Zia gains target-typed list combinators — `map`, `filter`, `reduce`, `firstWhere`, `any`, `all`, `sum` — that infer their lambda parameter types from the element type and lower to plain loops.
- A correctness pass adds `for`-in over a String, range patterns in `match`, and `final`/`let` fields, and rejects chained comparisons with a clear message.
- Runtime object types carry across the language boundary now: member chaining type-checks in Zia, and BASIC reports a proper `B2001` on a mismatched object assignment instead of failing later during IL verification.
- A Zia program can import twice as many files. The resolver's ceiling moves from 256 to 512 imported modules, with the depth limit, the 64 MiB aggregate source cap, canonical-path deduplication, cycle handling, and the `V1000` diagnostic unchanged — so a large application compiles as one ordinary unit instead of pushing you toward monolithic files.
- A module variable is a module variable wherever you declare it. A Zia function lowered before the module `var` it assigns resolved that name to a fresh local slot instead of the module variable — well-formed IL that wrote to the wrong storage, with no diagnostic, so later readers still saw the declared initializer and textual order alone decided whether the assignment took effect. Mutable module variables now register in a pre-pass alongside functions, enum values, and `final` constants, so a setup function written above the declarations it assigns behaves exactly like one written below them.
- A module variable holds its references properly. Storing a string or an object into a module variable borrowed the reference rather than retaining it, and released the previous occupant before the replacement was in place — so a long-running program could read freed memory or leak the value it overwrote. Ordinary, qualified, and initializing stores all go through one managed path now: the incoming value is retained, and the outgoing one is released only after the replacement has landed.
- A local declared inside a loop stops accumulating. Each pass through the declaration allocated another slot, so a `var` inside a hot loop grew the interpreter's bump allocator without bound and a game loop running for millions of iterations would eventually exhaust it. Non-escaping fixed-size slots are hoisted to the function's entry block after lowering, so the loop reuses one; anything that escapes through a value, a call, a branch argument, or an exception region is left exactly where you wrote it.
- The Zia frontend closed its own hardening audit. The editor document-sync path parses its messages strictly, decodes Unicode escapes correctly, bounds how much a batch can grow a document, and applies each batch atomically in revision order. The lexer bounds what it retains from an oversized numeric literal and can't overflow on lookahead, import limits apply the same whether a module comes from disk or an editor, and completion clamps cursor coordinates before it indexes anything — so a broken or hostile editor talking to the compiler service gets a clean error, never undefined behavior.

### Packaging and installers

- The Windows toolchain setup is a native installer: a statically linked, high-DPI host with signed payloads, journaled rollback, and a full install, upgrade, modify, repair, and uninstall lifecycle, including per-user and all-users scope and an Apps & Features entry. Unicode install paths work throughout.
- Setup wears the Zanna Games brand. Welcome, maintenance, transaction confirmation, license acceptance, progress, and completion are a native shell drawn in the Zanna palette, with the Z mark and a green-to-teal compile rail rendered as vectors at your display's DPI — no bitmaps, so it stays sharp on any monitor. Accessibility didn't get traded away for it: every action is a real focusable Windows control carrying its full accessible name, Tab and Enter and Space behave natively, focus is visibly outlined, pages scroll when they don't fit the work area, and high-contrast mode replaces the brand colors with system ones. Silent installs still run with no UI at all.
- That installer now ships Zanna Studio, and standalone apps package as AppImage, RPM, DMG, and Windows installers with desktop launchers and icons. `zanna package --dry-run --json` is there for scripting.
- Every artifact passes a structural check and emits a SHA-256 checksum and a machine-readable manifest before it ships. `zanna install-package` refuses a package that doesn't match the target OS or architecture.

### Windows and Linux

#### Windows

- Every Windows build, test, and demo entry point is a PowerShell script now — `build_zanna_win.ps1`, `build_demos_win.ps1`, and the rest — working on both PowerShell 5.1 and 7, in place of the old batch files.
- A Windows adapter audit made the failure paths deterministic across sockets, entropy, locale, TLS, process launch, timed waits, and file watching, and the D3D11 backend builds cleanly under MSVC.
- Windows handles non-ASCII paths end to end. Your project can live under a path with any characters in it — a Cyrillic username, a Japanese folder name, an emoji — and compiling, importing, packaging, installing, and running all work. That covers source loading and imports, editor services, code generation and linking, the asset compiler and `.zpak` packages, toolchain manifests, the installer, and the runtime's own file, save-data, temp-file, and child-process handling. macOS and Linux keep their existing native path behavior.
- The Windows reliability review is finished. One theme runs through all of it: a Windows call that can fail is now treated as one that will. Every native object is validated before it is used or published, every partial result is released rather than left half-alive, and every replacement is staged so a failure leaves the last working version in place. The next few bullets are what that buys you.
- Rendering costs you a frame, not the session. A failed hardware Direct3D device retries Microsoft's in-box WARP driver before dropping to Zanna's software backend, so Remote Desktop sessions, virtual machines, and hosts with a weak display driver render instead of refusing to start. The D3D11 backend checks the exact descriptor of every buffer, texture, render target, view, query, sampler, and swap-chain surface before reusing or publishing it, compares COM objects by their true identity rather than by raw pointer, and requires each one to belong to the device that created it. Malformed readback, dynamic-buffer, snapshot, and morph-view caches are rebuilt instead of poisoning later draws; fallback textures publish as a complete set or not at all; and partial device and state outputs are released rather than left half-alive. None of it costs you a dependency — the identity checks use SDK-identical local constants, so the native link stays free of `dxguid`.
- What Windows writes, it writes completely. Runtime files open through wide, non-inheritable descriptors with explicit sharing modes, so Unicode paths survive to the last stdio boundary and no child process inherits a handle you didn't mean it to have. Saves, bakes, scene writes, probe grids, HTTP downloads, Studio builds, and demo generations flush, commit, and close durably, then replace their destination atomically — a failure leaves the previous good file exactly where it was, and a failed build preserves the last one that worked.
- Nothing that can fail to be created is assumed to exist. Locks, events, and threads are now created through checked calls across garbage collection, string interning, the 3D caches, assets, ZPAK, the HTTP/HTTPS/REST/SMTP/SSE/WebSocket stack, regex, promises, parallel work, scheduling, and threading; a failure unwinds the half-built state and reports it instead of raising out of a constructor. WASAPI audio negotiates formats, pauses, resets, and resumes without getting stuck, and its startup and teardown can no longer race or self-join.
- The Windows installer checks what it's installing. One shared native PE validator structurally checks every payload executable and packaged binary — architecture, headers, sections, extents, signature structure — before it is accepted, with a PowerShell twin applying the same policy to build scripts. Every signing, backup, and publish step verifies its destination before writing, the installer CLI rejects duplicate and empty arguments instead of guessing, and a cancelled install unwinds cleanly.
- Setup cleans up after itself, and says so honestly. The detached cleanup helper is reopened through a mutation-denying handle and re-verified byte for byte before it runs, directory and reparse-point substitutions are refused, a read-only attribute is restored if deletion fails, a target that has already vanished counts as success rather than an error, and a cleanup that could only be scheduled for the next reboot reports that instead of claiming it was done.
- Setup behaves like a native Windows app under stress. Enter activates the default button on every page, closing a nested installer window no longer swallows the application's own shutdown, a failed paint degrades instead of drawing garbage, and dragging setup to a monitor with a different DPI rebuilds its fonts, layout, controls, scrolling, and brand geometry at the new scale. A fast install can no longer flood the message queue with log updates, and every page and progress model is validated — labels, accessible names, action IDs, default and close actions — before a single window is created.
- Demo builds and packaging verify what they produce. A demo compiles once into a staged directory that must contain a valid PE32+ image of the requested architecture before that exact executable-and-asset generation is smoke-tested and transactionally published, so a failed build can't destroy the last good one, publish an x64 image as ARM64, or mix new code with stale assets. Each demo owns its assets in its own directory, asset directives parse with proper quoting and reject symlink traversal, output is bounded, and smoke runs happen in a private copy with a checked full-process-tree kill and bounded reap on timeout.
- A further 90-finding pass closed out the Windows alpha hardening. Direct3D 11 frame publication is transactional: a failure anywhere in a frame — target clear, main, instanced, skybox, or shadow draw, a constant-buffer contract fault, a dynamic buffer that won't allocate or map — latches the frame as failed, stops the work after it, and discards the depth probes, readback dirtiness, HDR state, presented color, and pending Present it would have published, so a partial frame can never replace a complete one. Frame counters advance only after the clear succeeds, and a failed shadow pass can't mark its atlas reusable.
- The embedded preview channel is role-safe and race-resistant. Studio's play channel maps both slots through one checked layout, proves the shared object's extents before and after remapping, requires genuinely lock-free process-shared atomics, and publishes its magic sentinel last. Duplicate hosts and producers are rejected, every entry point enforces whether the caller is the host or the producer, an abandoned or wrapped frame sequence is recovered rather than trusted, dimensions are read through a bounded seqlock, and a full input ring drops the newest event instead of corrupting the queue. Metadata tampered with after attachment is rejected, and resize state is published only once its event has actually been queued.
- Setup and updates check their inputs rather than assume them. An update is accepted only if its manifest authenticates byte for byte and its package identity, channel, architecture, version precedence, digest, and pinned HTTPS origin all hold up — checked once when the update is offered to you and again when it's launched. A package version has to parse against a canonical grammar before anything is derived from it, setup's cleanup step refuses malformed paths and reserved device names like `CON` or `LPT1` instead of acting on them, and a parent process ID that isn't plain digits yields a deterministic zero rather than a guess. Downloads negotiate TLS 1.3 over a TLS 1.2 floor, retried safely on Windows builds that don't recognize the newer flag.
- The Win32 adapters report failure instead of guessing. FILETIME converts on both sides of the Unix epoch without unsigned wraparound and saturates before narrowing, long sleeps split below Win32's infinite sentinel, audio refill shutdown polling is bounded, and reset, signal, wait, `IAudioClient` stop, and handle-close failures are diagnosed across the shared and WASAPI layers. Waitable-timer pacing distinguishes a timeout from an immediate failure, and DPI, client-rect, minimum-size, and timer-close failures are reported rather than papered over with guessed backing dimensions.
- The standalone native Zanna Studio links on Windows. The import planner now maps `CreateFileMappingA`, `OpenFileMappingA`, `MapViewOfFile`, and `UnmapViewOfFile` to Kernel32 and `expm1`, `fma`, `frexp`, `log1p`, and `scalbn` to the release or debug UCRT, so the embedded play channel and the hardened 2D physics math resolve at link time instead of failing closed at the final link. Governed by ADR 0232.
- Building Zanna on Windows works from a clean checkout. A fresh or reset build tree reaches configuration instead of failing on a clean step that had nothing to clean, and the optimized MSVC build is warning-clean under `/WX`. The platform lint gate batches its searches rather than spawning a process per file, so it finishes inside its timeout on a loaded machine. Building from source is also less of a wait when you aren't working on the IDE: `ZANNA_SKIP_STUDIO=1` on either the Unix or the PowerShell build script skips Zanna Studio's multi-minute native compile, and the setting is passed explicitly on every configure so a skipped run can't leave a stale one behind.

#### Linux

- The matching Linux audit hardened the X11/GLX, ALSA, inotify, and PTY paths and added a dependency-free headless graphics backend, so graphics code runs with no display server attached.
- Linux also gains a complete, dependency-free Wayland backend: `AUTO` prefers Wayland and falls back to X11, covering xdg-shell window management, fractional scaling, client-side decorations, full input with relative-pointer and IME protocols, EGL-accelerated `Canvas3D` presentation, and AT-SPI screen-reader export.
- The Linux platform review is complete too, closing out entropy, sockets, file watchers, PTYs, ALSA audio, Wayland, desktop portals, AT-SPI, and packaging. Backend selection under `AUTO` publishes atomically, so a failed Wayland probe can't leave you halfway between backends; clipboard transfers are bounded; and the Linux build wrapper works through symlinks and paths containing spaces.
- Machine queries are container-aware on Linux. CPU and memory readings resolve the active cgroup v1 or v2 controller, so a program running in a container or under a systemd slice sees its real limits — including fractional CPU quotas — instead of the host's hardware. AArch64 Linux is now documented as a supported target alongside x86-64.

#### Supported targets

- The supported-platform list is now accurate. macOS is Apple Silicon only — Intel Macs are not a supported target, because native linking on macOS x86-64 was never finished — and Linux covers both x86-64 and AArch64. The documentation used to claim more than the toolchain delivers; it now matches what actually links and runs.
- Native builds are stable on both: static archives no longer pull in unresolved libgcc/libstdc++ helpers, and the generated codegen tables are checked in for clean from-source builds.

### Tests, documentation, and demos

The test suite grew by about 69K SLOC alongside all of it. Every feature above landed with a test that failed before it and passes after, VM-versus-native probes keep the interpreter and compiled code producing the same answers, and byte-exact goldens pin scene files and the runtime's public surface so neither can drift quietly.

Documentation was reorganized into a topical hierarchy and reconciled against the live runtime registry, and a source-documentation pass put contracts, ownership rules, and invariants at each seam of Zanna's own tree. Closing it out: the VSCN scene format has a written specification, a twenty-minute tutorial takes a first 3D game from an empty project to a running scene, the 3D guide now covers the sky, time-of-day, reflection-probe, lens-flare, and node-animator classes that previously appeared only in the generated inventory, and each backend's remaining capability gaps — OpenGL point shadows, GPU timing outside D3D11, Metal statistics, the software renderer's unavailable reflection and HDR settings — are written down instead of left for you to discover.

The demos kept pace, and then they moved.
