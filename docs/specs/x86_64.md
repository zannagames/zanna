# Phase A Codegen Quickstart (x86-64 SysV)

## ABI snapshot

- **Calling convention:** System V AMD64.
- **Argument passing:**
    - Integer/pointer: RDI, RSI, RDX, RCX, R8, R9 then stack (8-byte slots).
    - Floating-point: XMM0–XMM7 then stack (16-byte shadow per spill).
    - Structs up to 16 bytes split across GPR/SIMD per ABI classes; larger by pointer.
- **Register preservation:**
    - Callee-saved: RBX, RBP, R12–R15 (plus stack pointer RSP). Preserve XMM callee-saves only if ABI extension
      requires (Phase A: none).
    - Caller-saved: RAX, RCX, RDX, RSI, RDI, R8–R11, XMM0–XMM15.
- **Return values:**
    - Aggregates >128 bits: caller allocates and passes pointer in RDI; callee writes there.
    - Float/vector in XMM0 (XMM1 if second part).
    - Integer/pointer/scalar ≤64 bits in RAX (plus RDX if >64 bits but ≤128).

## i1 lowering policy

- Native scalar stack slots are 8-byte addressable slots even for `i1`, `i16`, and `i32`; current GPR load/store
  lowering uses 64-bit moves. Packed byte/word stack storage is not part of this backend contract.
- On calls/returns, widen to full 8-byte slot (zero-extend) before passing or returning.
- Represent boolean SSA values as 0/1 in 64-bit GPRs.
- Widen `SETcc` byte results with `MOVZXrr8`; `MOVZXrr32` only zero-extends an already valid 32-bit value and must
  not be used as the first normalization step for an x86 condition byte.
- Normalize incoming `i1` parameters at function entry on both register and stack paths so backend code never observes
  non-canonical truthy values.

## Stack discipline

- Maintain 16-byte alignment at every call boundary. Adjust prologue to align `RSP` after pushing the return address.
- Spill slots allocated in 16-byte multiples when mixing SIMD/GPR spills; pure GPR spills may use 8-byte stride, but
  ensure call sites realign.
- Entry blocks that load stack-passed parameters keep a real frame even when the function is otherwise leaf-like, so
  positive `rbp` parameter offsets stay valid.
- `main` always gets the stack-safety runtime initialization call even when the function has no other frame pressure.
- On Win64, `main` also reserves the mandatory 32-byte shadow space for that injected runtime call even if the user
  function contains no ordinary calls.

## Block parameters to ParallelCopy

- IL block parameters become edge-specific ParallelCopy bundles in MIR. Each CFG edge owns one copy list executed before
  the successor block executes.
- Conditional and `switch_i32` edges lower through dedicated helper blocks so untaken edges do not execute another
  successor's block-argument copies.
- Ensure φ-like moves are ordered with ParallelCopy to avoid clobbers; insert temps when cycles exist.
- The x86-64 coalescer treats spilled copy operands as dependency locations too; stores to a spill slot must not run
  before every pending source read of that slot has been preserved.
- PX_COPY bundles are expanded during register allocation by `src/codegen/x86_64/ra/Coalescer.cpp`, which orders
  copies, breaks cycles via scratch registers, and handles spilled operands.

## Target-platform selection

- `CodegenOptions::targetPlatform` now drives assembly directives, native object format, symbol mangling, and native
  linker platform together.
- ELF output emits `.type` and `.note.GNU-stack`; Mach-O emits Darwin section names and underscore-prefixed binary
  symbols; COFF enables Win64 unwind metadata in native object emission.
- The x86-64 text assembly path applies Darwin `_` prefixes to function labels, direct calls, and non-local
  RIP-relative symbol references when targeting Mach-O. Internal branch labels such as `.L*` remain assembler-local.
- The CLI exposes this as `--target-darwin`, `--target-linux`, and `--target-windows`. `--target-win64` still selects
  the Win64 ABI and also implies the Windows platform policy.
- `--target-darwin` for x86-64 produces Mach-O objects and Darwin-flavored assembly only. macOS x86-64 is not a
  supported Zanna target — the native linker does not link it, and macOS support is Apple Silicon/ARM64 only.

## Phase A scope

- Implements instruction selection to MIR, linear scan register allocation, frame layout, and textual assembly
  emission (`asmText`).
- Implements post-RA scheduling, target-aware peephole cleanup, branch layout simplification, native object emission,
  and platform-specific assembly directives for Mach-O, ELF, and COFF.
- Defers: vector ABI oddities (mask regs, uncommon aggregate cases), shrink wrapping, pro/epilogue peepholes, and full
  symbolic debug info.

## Operation notes

- **Bitwise ops:** `LowerILToMIR` selects `AND`/`OR`/`XOR` for both register-register and register-immediate forms
  (see `src/codegen/x86_64/Lowering.Bitwise.cpp`).
- **Indirect calls:** `call.indirect` label operands are materialized with `LEA` and called through a GPR, matching the
  function-pointer path instead of silently becoming direct calls.
- **Overflow-checked arithmetic:** `LowerOvf.cpp` expands 64-bit overflow-checked arithmetic pseudos into guarded
  sequences. Sub-width annotated checked arithmetic is lowered earlier with explicit sign-extension and compare checks.
- **Signed & unsigned div/rem:** `LowerDiv.cpp` expands MIR pseudos into guarded `idiv`/`div` sequences and emits
  `rt_trap_div0` calls when the divisor is zero.
- **Checked signed div/rem:** `sdiv.chk0` also traps on `INT64_MIN / -1` via `rt_trap_ovf`. `srem.chk0` preserves the
  VM contract by returning `0` for `INT64_MIN % -1` instead of trapping.
- **FP-to-int casts:** `fptosi` performs explicit NaN and range checks. Checked FP casts call `rt_round_even`, perform
  explicit NaN/range checks, and report `InvalidCast` for NaN or negative unsigned inputs and `Overflow` for range
  failures. Checked casts use the destination width, not an unconditional 64-bit range.
- **Memory displacements:** x86-64 memory operands are limited to signed imm32 displacements. Larger IL constants are
  materialized with `mov` + `add` before the memory operation or GEP result is used.
- **ALU and compare immediates:** x86-64 register-immediate ALU and compare encodings accept only signed imm32
  constants. ISel keeps small constants in immediate form and emits `MOVri` into a temporary GPR for larger
  `ADD`/`SUB`/`AND`/`OR`/`XOR`/`CMP` operands.
- **Frame preservation:** callee-saved detection scans direct physical register operands and registers embedded in
  memory addresses. This matters when register allocation places a pointer/index value in RBX/R12-R15 on SysV, or in
  RBX/RSI/RDI/R12-R15 on Win64; those registers must still be saved even if they are never a direct instruction
  operand.
- **Liveness CFG:** local labels generated inside a block, such as branchy f64 select expansions, do not create
  inter-block successors. Branchy f64 selects emit explicit jumps to their join label so later layout changes cannot
  turn a select arm into fallthrough past the epilogue. Only the terminating `JCC` / `JMP` / `RET` sequence defines
  block CFG.
- **Branch layout:** trace layout only reorders functions whose inter-block control flow is fully explicit; implicit
  physical fallthrough blocks stay in source order. Branch-chain elimination rewrites every `JCC`/`JMP` target in a
  block, not just the final terminator. Cold-block movement keeps any block reached by implicit physical fallthrough
  adjacent to its predecessor.
- **Conditional MIR operands:** generated MIR uses `{condition, label}` for `JCC` and `{condition, destination}` for
  `SETcc`. Backend validators, emitters, and branch peepholes also scan by operand kind so older hand-built tests using
  `{label, condition}` or `{destination, condition}` fail consistently only when a required condition, label, or
  destination is actually missing.
- **Generated labels:** `MFunction::makeLocalLabel()` is function-stemmed before the numeric counter. Labels remain
  assembler-local, but they are unique across the full textual assembly module rather than only inside one MIR
  function.
- **Structured traps:** `idx.chk`, checked-narrowing, and checked-cast failures use `rt_trap_raise_error` instead of raw
  `ud2`. `ErrGetMsg` calls `rt_throw_msg_get`.
  Generic `trap` still emits a terminal fault, but now preserves any optional managed string payload by calling
  `rt_trap_string(payload)`.
- **Switch lowering:** `switch.i32` stays linear for very small case counts and switches to a balanced decision tree for
  larger case sets to reduce worst-case compare depth.
- **Assembly diagnostics:** unknown MIR opcodes are hard backend errors; the text emitter no longer comments them out
  and keeps going.
- **Post-RA scheduling:** optimized direct backend entry points and the modular pass pipeline run a conservative
  list scheduler after frame lowering. It splits on calls, terminators, stack mutations, div/rem lowering artifacts,
  and unresolved pseudos, then schedules dependency-safe segments by critical path.
- **Target-aware DCE:** peephole DCE uses the selected `TargetInfo`, so SysV and Win64 call argument live-ins differ
  for both GPR and XMM registers. Callee-saved registers are live at returns so frame-lowered restore loads are not
  deleted. EFLAGS-producing instructions are preserved only when a later conditional branch, setcc, or cmov consumes
  the flags.
- **Frame memory peepholes:** simple RBP-relative stores and reloads are forwarded to register moves when no barrier,
  overwrite, or source-register redefinition intervenes. Earlier stores to the same frame slot are removed when a
  later store fully overwrites them before any load or memory barrier. Integer and scalar-double accesses at the same
  RBP displacement alias the same eight bytes and therefore block stale forwarding/removal across register classes.

## Adding a new opcode

1. Introduce the MIR opcode in `src/codegen/x86_64/MachineIR.hpp`/`.cpp`, documenting operands, result class, and
   verifier hooks.
   Update any helpers or enumerations that surface the opcode to the rest of the backend.
2. Extend IL → MIR selection in `src/codegen/x86_64/LowerILToMIR.hpp`/`.cpp` (and the relevant `Lowering.*.cpp`
   specialization files; add a focused matcher in `ISel.hpp`/`.cpp` if needed).
   Keep selection predicates narrow so unrelated patterns are unaffected.
3. Map the opcode to a physical mnemonic inside `src/codegen/x86_64/AsmEmitter.hpp`/`.cpp`, keeping operand ordering
   consistent.
   Verify operand modifiers (e.g., `byte ptr`) match the intended encoding.
4. Update lowering helpers or post-processing passes (e.g., `LowerDiv.cpp` for div/rem, `LowerOvf.cpp` for overflow
   ops) if the opcode needs multi-instruction support.
5. Update the selection tests (e.g., `src/tests/codegen/x86_64/*`) with a focused case that exercises the new path
   end-to-end.
   Aim for a MIR dump and final assembly snippet to catch regressions early.
6. Regenerate or adjust any MIR/assembly golden files touched by the opcode, keeping Phase A invariants intact.
   Confirm stack alignment assertions still pass under `ctest`.

## Backend pipeline map

1. **IL to MIR lowering** (`LowerILToMIR::lower`, `LowerILToMIR.hpp`/`.cpp` + `Lowering.*.cpp` files): pattern-match
   IL ops to target MIR. Add new opcode translations here.
2. **Call lowering** (`CallLowering.hpp`/`.cpp`, invoked from `lowerPendingCalls` in `Backend.cpp`): expand CALL
   placeholders into argument-marshalling sequences.
3. **Instruction selection** (`ISel.hpp`/`.cpp`): rewrite generic MIR pseudos into target-specific ops
   (arith/compare/select).
4. **Division expansion** (`LowerDiv.cpp`): rewrite signed/unsigned div/rem pseudos into IDIV/DIV sequences. Checked
   pseudos keep divide-by-zero guards; optimizer-demoted plain pseudos lower without dead trap edges.
5. **Overflow expansion** (`LowerOvf.cpp`): rewrite overflow-checked arithmetic pseudos into guarded sequences.
6. **Parallel copy resolution** (`ra/Coalescer.cpp`): expand PX_COPY block-parameter bundles into ordered copies
   during register allocation, breaking cycles with scratch registers.
7. **Register allocation** (`RegAllocLinear.hpp`/`.cpp`, `ra/Allocator.cpp`, `ra/Coalescer.cpp`, `ra/Spiller.cpp`):
   map virtual regs to physical; insert spills/reloads.
8. **Frame/stack planning** (`FrameLowering.hpp`/`.cpp`): assign spill slots and emit prologue/epilogue.
9. **Post-RA scheduling** (`Scheduler.hpp`/`.cpp`): reorder conservative dependency-safe segments when optimization
   is enabled.
10. **Post-RA cleanup** (`Peephole.hpp`/`.cpp`): peephole optimizations applied after register allocation; returns
   number of transformations applied. Set `ZANNA_CODEGEN_STATS=1` to emit backend peephole transformation counts plus
   MIR function/block/instruction, call, branch, load, and store counts as codegen diagnostics.
11. **Emitter** (`AsmEmitter.hpp`/`.cpp`): produce final assembly text and manage rodata pools.
12. **Binary emitter** (`binenc/X64BinaryEncoder.cpp`, `passes/BinaryEmitPass.cpp`): encode machine code and write
    object sections directly for native assembly mode.

- To add a new lowering pass, slot it before RA if it rewrites SSA, after RA otherwise; update `Backend.cpp`'s
  pass wiring if it operates on MIR.

## Debugging checklist

- Check MIR output at each pipeline stage to trace lowering/allocation decisions.
- Inspect emitted assembly by reading `asmText` from the compiled function object.
- Use targeted `dbg()` prints inside lowering stages; guard them with compile-time flags to keep release builds quiet.
